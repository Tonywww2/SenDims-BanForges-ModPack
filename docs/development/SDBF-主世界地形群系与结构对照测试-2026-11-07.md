# 主世界地形、群系与结构对照测试

测试日期为 2026-11-07。测试通过命令行运行独立 Forge 服务端、新建固定种子世界，并采集 JFR。

## 核心结果

本轮普通开图样本中，主要负担集中在复杂噪声地形，以及结构起点生成期间的理论高度探测。AE2 陨石的一次起点生成耗时约 27 秒，是本轮最突出的单次停顿。Tectonic 的复杂地形计算会放大这种密集高度查询的成本。

关闭 Tectonic 生成后，总请求耗时约减少 65.5%。单独关闭 AE2 陨石自然生成后，约减少 45.4%。两种干预作用于同一条调用链的不同位置，收益存在重叠。

## 环境与方法

- 使用当前整合包的服务端测试副本，Forge 47.4.10、Java 21.0.5、ZGC，堆大小 4–10 GiB，Smooth Boot 主工作线程配置 27。
- 测试机器为本机 i7-13700K。正式测试统一使用 JFR 调用栈深度 256。
- 测试副本排除了 9 个阻止专用服务端启动的客户端组件及其强制依赖，并在两份重复 Carbon JAR 中保留 `1.20.1.9-A`。这些条件在全部普通开图组之间一致。
- 世界种子为 `20261107`。每组启动独立 JVM、创建全新世界，完成初始化及 64 个 FULL 区块请求预热后开始计时。
- 测量三个互不相邻的 8×8 区域，左上角区块坐标分别为 `(1024,1024)`、`(2048,-1024)`、`(-2048,1024)`，每组共 192 次 FULL 请求。
- 使用服务端同步请求区块，包含生成所需的邻块依赖。基准 JFR 中包含 2700 个 structure_starts、588 个 biomes、432 个 noise 阶段事件。
- 测量时没有在线玩家，自然刷怪、昼夜天气变化和随机刻关闭。测量对象为区块生成路径，客户端网格、渲染和网络不在这组计时范围内。
- 计时从预热后开始，启动、配方注册、退出保存均单独进行。请求计时分辨率为 1 ms。

基准样本的地表群系包括 RU 寒带针叶林、河岸与砾石海滩，以及深海、冰冻海洋和少量 RU 地下群系。该区域组合适用于本轮固定路线对照，尚未覆盖所有气候带、稠密森林或大型建筑遭遇场景。

### 分组的实际操作

- Tectonic 通过测试副本的 `general.mod_enabled=false` 关闭生成。
- Terralith 通过停用其测试副本 JAR 完成。同步调整了三份引用其群系、地物的测试数据，使其他维度和标签可以完成注册。
- RU 保留模组与注册资源，将主世界 primary、secondary、rare 三个区域权重设为 0。样本群系输出用于核验其生效情况。
- 结构通过数据覆盖将对应 `minecraft:random_spread` 放置组的 `frequency` 设为 0。全部额外结构组共覆盖 159 组，AE2 为 1 组，ATi 为 6 组，Dungeons Arise 为 2 组。
- 结构干预保留模组本身及物品、方块、结构定义。代码直接生成的地物、非 random_spread 放置类型和原版结构另按原有规则运行。

## AE2 陨石与地形计算的组合热点

### 直接证据

正式基准中，区块 `(1033,1041)` 的 `minecraft:structure_starts` 阶段耗时 **26.851 秒**。校验轮同一位置耗时 25.112 秒。保存的该区块 NBT 中有有效的 `ae2:meteorite` 起点。

调用链如下。

```text
ChunkGenerator.createStructures
  Structure.generate / GenerationStub.getPiecesBuilder
    appeng.worldgen.meteorite.MeteoriteStructure.generatePieces
      ChunkGenerator 的理论高度查询
        NoiseBasedChunkGenerator.iterateNoiseColumn
          NoiseChunk 的密度函数图转换与缓存构造
          CubicSpline / DensityFunctions.Spline
          噪声与含水层采样
```

对已安装 AE2 15.4.12 的字节码检查显示，`generatePieces` 为计算地形高度的均值和方差，遍历陨石周围的方形网格。半径由陨石大小派生，单次可以产生数百次理论高度查询。调用栈中的样条映射、构造、哈希和噪声采样与此对应。

在正式基准的 4563 个选定生成线程执行样本中，`MeteoriteStructure.generatePieces` 包含子调用的样本数为 1479，约 **32.4%**。CPU 时间来自多个线程，该比例的分母与单次停顿的墙钟时间不同。

单独关闭 AE2 结构后，最长请求降到约 4.51 秒，总请求时间从约 59.82 秒降到 32.67 秒，进一步支持该调用链是本轮主要热点。

### 其他生成工作

正式基准按可见调用栈作互斥归类，结构上下文约占选定 CPU 样本的 **48.2%**，其余直接噪声路径约占 **43.2%**，地物约 **3.3%**，地表规则约 **1.5%**。分类优先保留结构调用上下文，因此结构内部的噪声计算计入结构类。

选定线程为 `Server thread` 和 `Worker-Main-*`。以上属于采样归因，比例受调用栈和分类规则影响。JFR 的阶段持续时间包含并行与等待，不能直接相加当作 CPU 时间。

基准 GC 暂停累计约 0.65–0.67 ms，光照约占选定 CPU 样本的 0.2–0.3%。本组长停顿主要对应生成计算。

## 大型模板的额外压力测试

普通开图样本中，ATi 与 Dungeons Arise 分组没有明显改善。为检查偶遇大建筑时的开销，另建世界，预生成放置区域后测试指定结构的同步放置时间与调用栈。该压力测试单独统计。

这两轮最初请求 flat 预设，但维度数据包将实际生成器覆盖为 `NoiseBasedChunkGenerator`。已通过存档和探针确认两轮均为该生成器，因此按预生成主世界中的结构放置比较记录。复现工具已显式选择 normal 预设。

每轮先预生成放置点周围 33×33 共 1089 个 FULL 区块，再启动 JFR 并执行 `place structure`。两份放置窗口 JFR 中均未出现新区块生成阶段事件。

| 指定结构 | 同步整座放置时间 | 预生成区域的耗时 |
| --- | ---: | ---: |
| `ati_structures:steam_house` | 0.863 秒 | 82.781 秒 |
| `dungeons_arise:keep_kayra` | 23.767 秒 | 83.655 秒 |

同步整座放置覆盖多个区块，包含首次结构规划、模板读取与方块放置。预生成耗时单独列出。每座结构测试一次，这个口径与普通开图的 192 次请求分别解释。

### Structure Gel API 的模板检查成本

`keep_kayra` 放置窗口取得 682 个选定执行样本。其中 `StructureTemplate.processBlockInfos` 包含子调用约占 **76.8%**。进一步定位到 Structure Gel API 2.16.2 的注入函数 `TemplateMixins$StructureTemplateMixin.addGelProcessor_processBlockInfos`，其子树约占 **44.1%**，内部逐条检查方块是否实现 `IStructureGel` 的 lambda 自身约占 **37.7%**。这些范围互相包含。

已核对该版本字节码。处理链会对方块信息列表执行 `stream().anyMatch(...)`，确认是否需要加入 `RemoveGelStructureProcessor`。模板放置涉及多个区块，处理链随之重复进入。城堡主模板包含 1236233 条方块记录，其数据中没有出现 `structure_gel:` 命名空间标识。

这项结果确认了大模板放置的另一处具体开销。针对模板、调色板缓存 Gel 判定结果，以及优化全量方块列表的重复处理，是后续保留建筑内容时可验证的方向。涉及实际 Gel 方块、结构处理器和资源重载的行为需要保持一致。

ATi 蒸汽屋的窗口只有 31 个执行样本，适用于确认调用路径，细分百分比的统计精度有限。

## 当前可采用的取舍

1. 保留 AE2 工业内容，将专项优化定位到陨石生成的密集理论高度查询，以及复杂密度函数图在列查询中的重复工作。
2. 需要直接降低开图成本时，Tectonic 生成开关是本轮收益最大的已测单模组干预，但会改变新区块地形。
3. Terralith 的差异小于 Tectonic。RU、ATi、Dungeons Arise 在本组普通区域中的差异较小。`keep_kayra` 的整座放置仍有明显成本，适合单独处理巨型结构的频率和模板处理链。
4. 预生成主要探索范围可以将这些计算提前完成。数据驱动结构频率也可按具体热点分别调整，需同时维护整合包的资源和流程需求。

具体保留内容的代码优化尚未在本轮实施，其收益需要独立验证。
