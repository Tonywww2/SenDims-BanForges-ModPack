# 龙之研究护盾：改到扣血前结算

2026-11-05。适用 Draconic Evolution 3.1.2.621、Forge 47.4.10、SenDims 1.1.1（本次构建）。

## 结论

龙之研究（Draconic Evolution）模块护甲的护盾，原本分两处结算：

- `LivingAttackEvent`（LOW）：护盾点数 ≥ 原始伤害 × 类型系数时，整次取消并扣盾。此时还没有经过护甲、保护、难度倍率。
- `LivingDamageEvent`（LOW）：护盾不够时，用剩余点数抵扣，并把**加权后**的剩余直接作为伤害。

现在改为只在最后一步结算：`ForgeHooks.onLivingDamage` 返回前，也就是所有 `LivingDamageEvent` 监听者处理完之后、`setHealth` 扣血之前。玩家和普通生物都走这一步。

| 情况 | 原来 | 现在 |
| --- | --- | --- |
| 扣盾依据 | 原始伤害 | 最终伤害（护甲、保护、吸收值、难度倍率、⑧ 层修正之后） |
| 护盾够 | 攻击事件取消 | 本次伤害归零，不扣血，并跳过受伤流程的剩余部分（见下） |
| 护盾不够 | 剩余 = 加权伤害 − 护盾，直接扣血 | 剩余按类型系数换算回实际伤害后扣血 |
| 环境伤害（火焰、着火、岩浆、岩浆块、卡墙窒息、挤压、仙人掌） | 攻击事件中格挡 | 不变 |
| 不死模块 | 攻击/伤害事件中，无敌期间取消 | 不变 |

类型系数是 DE 自己的规则：`bypasses_armor` 伤害 ×3，魔法再 ×2。原版魔法同时属于 `bypasses_armor`，合计 ×6；原版 `generic` 也属于 `bypasses_armor`。

例：魔法伤害 4 点，护盾剩 3 点。加权 24，原来剩余 21 点直接扣血，比没有护盾还多；现在扣 4 × 21/24 = 3.5 点。

## 护盾挡满时

护盾挡满后，`hurt` 剩余的流程直接跳过，受伤冷却恢复成被打之前的状态，`hurt` 返回 false。攻击方因此按"没打中"处理，和龙之研究原本在攻击阶段取消一致。护甲耐久推迟到护盾判断之后，挡满就不扣。

| 效果 | 挡满时 |
| --- | --- |
| 被打方击退、攻击方附加击退（击退附魔、疾跑、怪物击退属性） | 不触发 |
| 受伤冷却（20 tick 无敌帧） | 不触发，恢复为被打前的状态 |
| 红闪、受伤音效、镜头晃动 | 不触发 |
| 记录攻击者（宠物替主人反击、怪物反击目标、击杀归属） | 不触发 |
| 头盔被落块砸掉耐久 | 不触发 |
| 攻击方命中效果（荆棘、武器耐久、横扫、附魔/词缀命中效果、斧头破盾） | 不触发 |
| 箭矢 | 弹开 |
| 护甲耐久 | 不扣 |
| 黄心 | 照常先于护盾扣除 |
| `LivingHurtEvent` 阶段的效果（魔虚罗适应、圣骑士护盾分担、美德斗篷、狂战士之怒自伤） | 照常 |
| `LivingDamageEvent` 阶段的效果（伤害数字、吸血手套、魔虚罗记忆、役满大地） | 照常，看到的是护盾抵扣前的数值 |
| 原版盾牌格挡、惊醒 | 照常 |
| 龙之研究自己的护盾受击音效和动画 | 照常 |

最后三类发生在护盾判断之前，无法撤回。

其他说明：

1. 护盾被打穿（没挡满）时一切照常：击退、冷却、护甲耐久都正常结算。
2. 挡满的攻击不留受伤冷却，10 tick 内的连击每一下都单独扣盾，和龙之研究原本一致。拔刀剑连段、箭雨这类多段攻击掉盾会比较快。
3. 黄心整段吃掉的伤害（到护盾时已为 0）不算护盾挡住，按原版处理。
4. 护盾消耗整体下降：减法护甲和难度倍率之后的伤害通常远小于原始伤害。

## 实现

SenDims，均只在装有 Draconic Evolution 时加载：

- `mixin/draconicevolution/ShieldControlEntityMixin`：`tryBlockDamage(LivingAttackEvent)` 在环境伤害格挡之后直接返回，不再做整次吸收。
- `mixin/draconicevolution/ModularArmorEventHandlerMixin`：`onEntityDamaged` 里调用护盾的那一步改为空操作；不死模块的检查保留。
- `mixin/draconicevolution/ForgeHooksDraconicShieldMixin`：`ForgeHooks.onLivingDamage` 返回前交给 `DraconicShieldFinalStage.finalDamage`。注入在 `ForgeHooks` 内部，TetraModify Core 包在调用处的 `WrapOperation` 不影响它。
- `mixin/draconicevolution/LivingEntityDraconicShieldMixin`：在 `LivingEntity.hurt` 的冷却判断处记下被打前的 `invulnerableTime`、`lastHurt`；`actuallyHurt` 前后开、关一个记录帧（可嵌套）。护盾挡满时恢复这两个值并返回 false。
- `mixin/draconicevolution/LivingEntityDraconicArmorMixin`：在 `getDamageAfterArmorAbsorb` 调用 `hurtArmor` 处，若穿着有点数的护盾就先暂存；护盾判断后没挡满再扣，挡满则丢弃。在调用处拦截，GeoTetraArmor 挂在 `Player.hurtArmor` 开头的耐久逻辑只会执行一次。
- `compat/draconicevolution/DraconicShieldFinalStage`：找到胸甲（或饰品栏）的护盾控制模块，用一个不发布的 `LivingDamageEvent` 调用 DE 自己的 `tryBlockDamage`，所以护盾点数、增益、冷却、受击动画、音效与 DE 一致；剩余伤害按类型系数换算回实际伤害；标记记录帧。
- `compat/draconicevolution/ShieldHurtFrame`、`ShieldHurtTracker`：记录帧和 `LivingEntity` 上的接口。
- `mixin/draconicevolution/ShieldControlEntityAccessor`：调用 DE 的类型系数方法；GameTest 用来设置护盾点数。

兼容性：扫描了 `mods/` 全部 365 个 JAR（含内嵌 JAR）的 Mixin，没有其他模组改写 `hurt` 里的 `actuallyHurt` 调用或 `getDamageAfterArmorAbsorb` 里的 `hurtArmor` 调用。

## 验证

`gradlew runGameTestServer -PexcludeGiselleFromServerRuntime`，`gametest/DraconicShieldGameTests` 四项全部通过：

- `attackStageNoLongerAbsorbs`：护盾 10 点、近战 4 点，攻击事件不再被取消，护盾不变。
- `finalStageAbsorbsWithoutWeightedLeak`：护盾够时伤害归零、扣 4 点；护盾 3 点时剩 1 点；魔法 4 点、护盾 3 点时剩余按系数换算，小于 4。
- `shieldRunsAfterEveryDamageListener`：尸壳穿双足飞龙胸甲并装护盾控制模块，真实调用 `hurt`。LOWEST 监听者看到完整伤害；护盾 1000 点时血量不变、护盾减少的正是最终伤害，`hurt` 返回 false，无受伤冷却、无受伤动画、无击退；护盾 1 点时扣血 = 最终伤害 − 1，`hurt` 返回 true，冷却 20、受伤动画 10、有击退。
- `armorDurabilityWaitsForTheShield`：玩家穿铁头盔、铁护腿、铁靴子加双足飞龙胸甲。护盾挡满时铁甲耐久不变、无受伤冷却；护盾被打穿时铁甲照常掉耐久。

同次运行中 `hiddenmarksandapcommit`（役满）失败，此前几次运行也失败，与本改动无关。打包后的 jar 已核对 refmap 与重混淆后的字段/方法名。未进游戏实测。
