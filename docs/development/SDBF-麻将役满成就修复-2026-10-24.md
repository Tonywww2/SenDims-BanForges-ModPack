# 麻将役满成就未完成修复

用户反馈胡出大三元、国士无双后，对应成就没有完成。目标版本为 Minecraft 1.20.1、Riichi Mahjong Forge 0.2.0、HotAI 1.0。

## 已确认的错误

直接检查本机模组 JAR，并执行其真实方法字节码，确认结算广播与成就判定使用的数据不一致：

1. `MahjongTableBlockEntity.playFinalWinEffects` 从 `WinResult.yaku()` 构造普通役列表，从 `WinResult.yakuman()` 构造役满列表。
2. 两份列表都传给 `MahjongWinEffects.playWinEffects`。役满列表用于聊天广播，因此玩家可以看到“大三元”“国士无双”的役满提示。
3. `playWinEffects` 调用 `MahjongYakuAdvancements.awardForWin` 时只传了普通役列表，遗漏役满列表。
4. `awardForWin` 虽然根据布尔标记添加通用 `yakuman`，却不知道具体是哪种役满，因此没有授予 `yaku/daisangen` 或 `yaku/kokushi_musou`。

两种役满在原代码中均复现：役满广播正常，通用 `yaku/yakuman` 完成，具体成就及其证书奖励没有触发。这是原模组的传参遗漏；v3 设置入口补丁没有改变这段结算代码。

当前 KubeJS 的具体役满成就仍使用原模组的 `earned` 条件与 `minecraft:impossible` 触发器。这种成就需要 Java 代码主动授予，不能单靠条件自动检测胡牌；触发器本身不是本次错误。数据包为这些原生成就附加了证书战利品奖励，FTB Quests 再检查对应证书物品，因此故障也会影响相关任务。

## 修改

只新增 `com/riichimahjongforge/mahjongcore/MahjongWinEffects.class` 的 HotAI 修复，不覆盖已有 v3 的两个牌桌类。

在原有普通役判定调用之后，增加对役满列表的同一判定调用：

```java
MahjongYakuAdvancements.awardForWin(winner, han, yakuman, yakuNames);
MahjongYakuAdvancements.awardForWin(winner, han, yakuman, yakumanNames);
```

沿用原 `grant` 的完成状态检查：已完成的条件不会重复授予，所以同一成就的首次完成奖励不会因为多调用一次而重复发放。役满广播、音效、麻将之星发放及结算事件保持原逻辑。

检查真实核心枚举时，还发现六个名称与既有成就 ID 的对应遗漏，一并加入 `canonicalYakuKey`：

| 核心名称规范化后 | 既有成就键 |
| --- | --- |
| `chihou` | `chiihou`（地和） |
| `iipeiko` | `iipeikou`（一杯口） |
| `seat_wind` | `yakuhai_jikaze`（自风） |
| `round_wind` | `yakuhai_bakaze`（场风） |
| `ittsu` | `ikkitsuukan`（一气通贯） |
| `chiitoi` | `chiitoitsu`（七对子） |

没有修改胡牌判断、役种成立条件、计分规则、成就父子关系或奖励数量。核心未区分的特殊双倍役满不会由本补丁额外识别或授予。

## 验证

[TestMahjongAdvancements.java](../tools/server_bugs_2026_10_24/TestMahjongAdvancements.java) 直接执行现有 v3 牌桌的 `playFinalWinEffects`、原始/补丁版 `MahjongWinEffects` 和原始 `MahjongYakuAdvancements` 方法。使用真实 `WinResult`、`Yakuman`、`NonYakuman` 类型与现有成就/证书数据文件。

- 新增 819 项断言通过，覆盖核心全部 13 类天然役满、30 种普通役、累计役满。
- 三人局、四人局的每个获胜座位均获得自身对应成就，其他玩家不会获得。
- 多重役满分别授予；多个获胜结果分别归属对应玩家；机器人/离线获胜者不会把成就发给其他玩家。
- 相同成就重复判定不重复授予首次奖励，普通役和累计役满的行为保留。
- 检查证书奖励表存在且物品 ID 对应；空列表、重复役名、未知役名及流局不产生错误授予。
- 真实 HotAI `.class → .badiff → 再加载` 往返一致，ASM 与 JVM 校验通过。
- 既有 80 项回归与 117 项交互断言也通过，共 1016 项。交互测试现在直接重建并校验历史 v2 类指纹，无须保留旧发布 ZIP。
- 生成的原三个修复类 SHA-256 与之前版本完全相同，本次只安装和发布新的结算类。

Minecraft 玩家/世界、成就进度保存、奖励发放、音效及事件总线使用测试替身。因此验证确认了方法调用、成就 ID、获胜玩家和证书配置的对应关系，尚未完成远程完整模组环境中的实际成就弹窗与物品到账验证。

## 安装与已错过的成就

[下载成就增量补丁](../releases/SDBF-Mahjong-Advancements-HotAI-2026-10-24.zip)，可以与已安装的 v3 同时使用。

1. 完全停止服务端。
2. 若 `hotai/com/riichimahjongforge/mahjongcore/` 已有 `MahjongWinEffects.class` 或 `.badiff`，备份到整个 `hotai` 目录之外，再移走原位置的旧文件。
3. 合并包内的 `hotai/` 到服务端根目录，保留所有其他补丁，完整重启。首次加载后 HotAI 将 `.class` 转为 `.badiff` 并移除 `.class` 是正常行为，不要再次叠加 `.class`。

本地整合包也已安装此类，重启后生效；联机修复需要远程服务端安装，联机客户端无需安装。`/reload` 不会加载字节码修复。

修复只对后续结算生效，不能自动回溯已经结束的牌局。对于用户确认已经完成的大三元、国士无双，可在对应玩家在线时，由 OP 在游戏中执行（替换 `玩家名`）：

```mcfunction
/advancement grant 玩家名 only riichi_mahjong_forge:yaku/daisangen
/advancement grant 玩家名 only riichi_mahjong_forge:yaku/kokushi_musou
```

这是补发具体成就，不授予其他役满。远程服包含当前 KubeJS 奖励数据时，首次完成会随成就发放相应役满之证；如果成就已经完成，这两条命令不会重复发放证书。没有执行远程补发，也没有修改任何玩家进度文件。
