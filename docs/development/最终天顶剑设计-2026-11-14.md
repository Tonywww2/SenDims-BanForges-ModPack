# 最终天顶剑设计

日期：2026-11-14。状态：已实装，待实机验证（第 10 节）。

相关：[天顶·伪系列](../kubejs/zenith-series.md)、[仪式着色器特效设计](仪式着色器特效设计-2026-11-13.md)（光影兼容的做法在那里验证过，本设计沿用）。

已定：

- 配方用五把天顶剑和万象合金锭合成。
- SA 为「真·次元斩」，用着色器做出次元斩·终那样的演出和威力：先是满屏的斩击，再是画面定格、碎裂。
- SE 不沿用天顶系列"前置 SE 去重全加"的规则，单独设计「天顶」「裂空」两个（第 6 节）。
- 模型为原创设计，见第 7 节。
- 第 9 节的十项已于 2026-11-14 确认，正文已按确认结果改写。

## 1. 定位

天顶系列的终点：魔剑、黑冠、神威、王权、暗咒五把伪天顶合一。

- 名称「天顶·裂空」，命名刀 ID `slashblade_sendims:zenith_final`。
- 和四把伪天顶一样，定义写在整合包的命名刀 JSON：`kubejs/data/slashblade_sendims/slashblade/named_blades/`。SA 和视觉实现放在特供模组。
- 模型和贴图放在特供模组（`slashblade_sendims:model/zenith_final/`），和圣剑、水执一样。原因是模型的发光分组要采样特供模组的着色器画布（第 7 节）。
- 不再用"攻击、耐久取前置最大值，附魔逐项取最高，SE 全并"的继承规则。数值见第 3 节，附魔与 SE 见第 6 节。

## 2. 配方

工作台合成，写在 `kubejs/server_scripts/recipes/zenith.js`，用拔刀剑的有序合成 `slashblade_shaped_recipe`：

```text
A O B
O E O
C O D
```

| 键 | 物品 |
| --- | --- |
| A | 魔剑：`sjap_adder:dragon_steel_ice` |
| B | 黑冠：`slashblade_sendims:zenith_false_black_crown` |
| C | 神威：`slashblade_sendims:zenith_false_divine_might` |
| D | 暗咒：`slashblade_sendims:zenith_false_dark_curse` |
| E | 王权：`slashblade_sendims:zenith_false_kingship`，放中间 |
| O | 万象合金锭 `kubejs:omni_alloy_ingot`，共 4 个 |

- 五把都用 `SlashBladeIngredient` 按名字指定，门槛各为 杀敌 30000／耀魂 300000／锻造 150。
- 拔刀剑有序合成的结算方式：成品的耀魂与杀敌数取所有刀的合计，锻造次数取最高值，附魔逐把合并。这是从拔刀剑本体的配方结算代码看出来的，实装时进游戏核对一次。
- 五把天顶都会被消耗。

## 4. SA：真·次元斩

### 4.1 演出流程

一次释放约 4.5 秒（90 tick）。所有时间点由服务端在释放时一次性下发，客户端按时间表播放。

| tick | 阶段 | 服务端 | 施放者看到的 |
| --- | --- | --- | --- |
| 0–8 | 起势 | 施放者定身（空中释放时原地悬停）、无敌；范围内目标进入"凝滞"（4.3） | 刀鞘亮起，视野边缘轻微变暗，环境声压低 |
| 8–40 | 乱斩 | 每 2 tick 对范围内每个目标结算一次斩击伤害 | 范围内的空间里不断出现长条斩痕（画在世界里，有透视、会被方块挡住），斩痕两侧的空间被拉开、错位 |
| 40–56 | 定格 | 停止结算；凝滞持续 | 整个画面（含小地图等 HUD）冻结、褪色发冷，斩痕发亮 |
| 56–60 | 收刀 | — | 施放者收刀，刀镡合拢；裂纹从定格画面里的斩痕处沿斩痕方向裂开，贯穿全屏（54–59 tick） |
| 60–80 | 碎裂 | 第 60 tick 结算终结伤害，冲击波 | 冻结的画面沿裂纹碎成碎片，碎片分离、坠落，碎片后面直接是实时画面；白光闪过 |
| 80 | 结束 | 解除凝滞和定身 | 碎片淡出完毕 |

### 4.2 判定与数值

- 基础伤害：对每个目标取一次 `AttackHelper.calculateTotalDamage(user, target, 1.0, false)` 并缓存，与圣剑、宿傩等现有 SA 的做法一致。
- 目标：沿用拔刀剑的目标筛选（`TargetSelector`），与其他 SA 一致；友伤开关和队伍规则照常生效。
- 乱斩：16 次，每次 0.5 倍基础伤害，共 8 倍，物理伤害。
- 终结：7 倍物理加 7 倍魔法（`indirectMagic`），共 14 倍。
- 合计 22 倍，是整合包里最高的 SA。对照：誓约胜利之剑约 14 倍，无名三重 12 倍，伏魔御厨子 7.5 倍。
- 范围：以施放者为中心，水平半径 24 格、上下各 12 格，不需要视线。
- 消耗：AP `[400, 0.35]`（固定 400 加 AP 上限的 35%）。没有冷却（2026-11-14 移除）；施放期间不能再次释放。
- 释放条件：除原生 SA 自身的判定外不加额外条件，地面、空中都能放。施放期间施放者无敌、定身，空中释放时原地悬停。
- 放出后一定放完：打开背包等界面、切换手持物品都不会打断（2026-11-14 取消这类限制），只有施放者死亡、离开维度或下线时提前结束。换掉手持物品后，伤害结算用施放时的那把刀。
- 定身会把移动速度属性压到 0，原版会因此把视野缩小一半；施放期间施放者的视野保持不变。

### 4.3 凝滞

- 作用对象：被这次真·次元斩选中的目标。以新的状态效果实现，到期自动失效，不往实体上写持久化的 NoAI，服务器中途关闭也不会留下状态。
- 普通生物：移动速度降到 0，攻击和射击取消，击退无效。
- 首领（`#forge:bosses`）和玩家：只减速 80%，不完全定住。首领这样处理是为了不卡住它们的攻击状态机，包括 Boss 重构的状态机。

### 4.4 与原生 SA／SSA 的关系

- 按现有 SA 的接法实现：注册原生 ComboState，在 `PerformSlashArtEvent` 里开始演出，AP 消耗写进 `sa_ap_cost.js`。参考 `HolySwordArts`、`SukunaArts`。
- 不做超级 SA（SSA）版本。

## 5. 视觉实现

### 5.1 原则

沿用仪式特效已经验证过的光影兼容方案：

- 世界里的东西用原版 `RenderType.eyes` 画（开光影时 Iris 会换成 `gbuffers_spidereyes`），光影的阴影阶段跳过。
- 自写着色器只在世界绘制之外运行：一是绘制前的离屏烘焙，二是光影最终合成之后的屏幕处理。
- 次元斩的屏幕层是全局最上层：挂在 HUD 画完之后（`Gui.render` 返回处），小地图、血条、快捷栏等 HUD 也一起定格、碎裂；打开的界面（暂停菜单、背包、聊天）画在它上面，照常可用。按 F1 隐藏界面时改在 `renderLevel` 之后。两处挂点都在 `GameRendererRitualScreenMixin`。

### 5.2 世界层：斩痕

- 乱斩的斩击只画在世界里，不在屏幕上画线（2026-11-14 修正）。
- 斩痕是细长的面片，长 14–30 格（2026-11-14 加长一倍以上）、宽 0.08–0.25 格，方向随机，绕自身轴线朝向镜头，存活 4–8 tick。出现时用 2 tick 沿长度方向"划开"。外面再套一层约 3 倍宽、亮度三成的光晕面片。
- 斩痕贴图在 CPU 上生成一次：亮白的芯、冷色的边、两端收尖，带细噪声。一次施放共 160 条，按种子生成，所有观看者相同；第 40 tick 时还在的斩痕定格到第 60 tick。
- 斩痕也送到屏幕层：每帧把最近 40 条投影到屏幕，在斩痕两侧做反向错位，表现"空间被切开"。错位带的宽度和强度按斩痕实际粗细和深度做透视，近处的切开得更宽，远处的细而弱。

### 5.3 屏幕层：定格与碎裂

1. **乱斩阶段**：屏幕层只加暗角和轻微褪色，再加上世界斩痕两侧的局部错位和色差（5.2）。不画屏幕切线。
2. **定格（第 40 tick）**：乱斩阶段每帧都把整帧画面（含 HUD）拷进同一个缓冲，第 40 tick 直接把这个缓冲留作"冻结图"，不另建缓冲再拷。此后看到的是这张图（褪色、偏冷），世界照常运行。
3. **裂纹（54–59 tick）**：从冻结图里屏幕上最长的斩痕中取最多 24 条，从斩痕中点沿斩痕方向向两端裂开，贯穿全屏；看得到的斩痕不足 10 条时（例如背对施放范围）用随机裂纹补足。
4. **切分**：在 CPU 上用这些裂纹依次切分屏幕矩形，得到一组凸多边形碎片。24 条线最多 301 块，只算一次。
5. **碎裂（第 60 tick）**：每块碎片按种子取一个位移方向、少量旋转和下落速度，作为一组带纹理的多边形画出来，纹理取最后一帧处理过的定格画面。碎片后面直接是实时画面，不画虚空底色（2026-11-14 移除，避免黑屏）。碎片边缘加一圈发光描边。
6. **结束**：碎片在第 72–80 tick 淡出。

线段数据通过一张小的浮点纹理传给着色器（原版着色器 JSON 不支持数组 uniform）。

### 5.4 网络与多人

- 新增一个次元斩阶段包，内容包括施放者 ID、中心点、半径、随机种子和起始 tick。发给 64 格内的玩家，协议号加一。
- 64 格内的玩家都能看到世界层的斩痕。
- 64 格内的玩家都会看到屏幕定格和碎裂，不只是施放者。客户端可以用配置关掉屏幕层。

### 5.5 配置与降级

- 客户端配置新增 `[zenithVisuals]`：`enabled`（次元斩全部画面）、`screenEffects`（屏幕层）、`flashIntensity`（白闪强度，0–1，对闪光敏感的玩家调低或设 0）、`bladeAnimation`（刀身特效动画，关掉时只画一帧静止画面）。
- 着色器加载失败或关闭屏幕效果时，只保留世界层斩痕和粒子，伤害和流程不受影响。

### 5.6 音效

- 不使用鬼泣的音效、语音和任何素材。
- 先用原版音效叠层：起势用低沉的嗡鸣，乱斩用快速的挥砍和玻璃碎响，收刀用金属合拢声，碎裂用碎冰声加音爆。
- 以后可以加原创音效资源。

## 6. 附魔与 SE（2026-11-14 定）

- 附魔：锋利 10、耐久 10（命名刀 JSON）。合成时五把天顶的附魔照常合并，同一附魔取最高等级。
- 实现在特供模组 `se/ZenithRiftEffects`；之前已经拿到的天顶·裂空由 `BladeDefinitionMigration` 补上这两个 SE 和附魔。

### 6.1 天顶（`slashblade_sendims:zenith_apex`）

- 斩击时（拔刀剑每次产生斩击），获得增幅 II，持续 5 秒，持续斩击时续上。已有更高等级的增幅时不覆盖。
- 手持这把刀时造成的伤害提高 `0.45 × (1 − 0.975^(x + 1))`，x 为刀上所有附魔的总等级：

| x | 提高 |
| --- | --- |
| 0 | 约 1.1% |
| 20（只有锋利 10、耐久 10） | 约 18.6% |
| 60 | 约 35.4% |
| 无穷大 | 45%（上限） |

### 6.2 裂空（`slashblade_sendims:sky_rift`）

- 斩击命中时，在命中的目标处释放一次空间斩；有锁定目标（48 格内）时，改为在锁定目标处释放。
- 空间斩以目标中心为圆心，对 3 格内的敌人各造成一次 0.5 倍的物理伤害（基础伤害的取法与真·次元斩相同），目标筛选沿用拔刀剑的规则。
- 1 tick 冷却：同一 tick 内只释放一次，所以一次挥刀命中多个敌人也只释放一次。空间斩本身的伤害不会再触发裂空。
- 画面沿用真·次元斩的世界斩痕：三道穿过中心附近、方向各异的斩痕依次划开，约半秒消失。通过次元斩阶段包的 CUT 阶段发给 64 格内的玩家，只画在世界里，没有屏幕效果。

## 7. 模型

不照着泰拉瑞亚的天顶剑还原，做一把原创的刀「裂空」。已按下面实装，预览见 `docs/model-previews/zenith-final.png` 和 `zenith-final-detail.png`。

- **刀身**：比原生太刀长约三成（332 对 255）的弯刀，镐造（刀背、镐筋、刃面、刃口），切先单独收尖。刀身正中有一道贯穿全长的空间裂缝。
- **刀镡**：素面深色圆镡，两面靠外缘各有一道细发光缝。不镶宝石。
- **刀柄**：黑色柄卷，菱形开口里露出深蓝鲛皮，两端是深色金属的缘和头。
- **刀鞘**：黑漆，鞘口和鞘尾是金属件，鞘身两面各有一道细裂缝。
- **刀身特效用着色器画，不用贴图**（2026-11-14 修正）：
  - 发光部件放在拔刀剑约定的 `*_luminous` 分组（叠加、全亮）。这些分组的 UV 不指向刀的贴图，而指向特供模组的一张 128×4096 画布 `slashblade_sendims:dynamic/zenith_rift/blade`。
  - 画布由着色器 `zenith_rift_blade.fsh` 在每帧开头（世界绘制之外）画一遍：刀身裂缝是折线形的开口，开口里是缓慢流向刀尖的深蓝星空和闪烁的星点，边缘一圈闪烁的亮边，每隔一会儿有一道能量脉冲从护手跑到刀尖；刀镡发光缝上有两颗亮点绕着转；刀鞘裂缝缓慢呼吸。
  - 特供模组在拔刀剑取发光材质时（`BladeRenderState.getSlashBladeBlendLuminous` 等三个方法）把这把刀的贴图换成画布，其他刀不受影响。手持、腰间、物品栏、掉落物看到的是同一帧动画。
  - 光影兼容沿用仪式特效的做法：自写着色器只在世界绘制之外运行，世界里仍是拔刀剑原生的发光材质按普通纹理采样，开光影时由光影包照常接管。
  - 最近 3 秒没有画过这把刀时不烘焙。配置 `bladeAnimation` 关掉时只画一帧静止画面。着色器加载失败时发光部件不显示，刀本身照常。
  - 刀的贴图（256×256）只画刀身、刀柄、刀鞘、金属件，裂缝下面是一条深色底，作为发光开口的背景。
- **制作流程**：`docs/tools/generate_zenith_final_model.py` 从零生成 OBJ 和贴图，输出到特供模组 `src/main/resources/assets/slashblade_sendims/model/zenith_final/`。坐标沿用原生 `blade.obj`：刀尖朝 -X，刀鞘沿刀身弧度，收刀时刀身在鞘内。物品栏姿势与天顶共用模型相同。预览里的发光层用 `docs/tools/bake_core_shader_preview.js` 在无头浏览器里跑同一份着色器得到。

## 10. 实装记录（2026-11-14）

特供模组（1.1.4，协议号 8 → 9）：

- `sa/ZenithRiftArts`：SA 流程、判定、伤害、凝滞、施放者无敌与定身、阶段包发送。连招状态 `true_judgement_cut`（停在原生次元斩收招姿势，约第 56 tick 进入原生收刀），SA 注册的超级版本也指向它。
- `effect/DimensionStasisEffect`：次元凝滞，I 级减速 80%，II 级速度归零；II 级目标造成的伤害和受到的击退由 `ZenithRiftArts` 取消。
- `network/ZenithRiftPacket`（编号 7）：START 与 END 两个阶段，发给 64 格内的玩家。
- `client/zenith/ZenithRiftClient`（世界层斩痕和光晕）、`ZenithRiftScreen`（屏幕层：斩痕两侧错位、定格、裂纹、碎裂、白闪；挂在 HUD 之后，碎片后面是实时画面）、`ZenithRiftBlade`（刀身着色器画布）、`ZenithRiftShaders`；着色器 `zenith_rift_screen`、`zenith_rift_blade`。
- Mixin：`GameRendererRitualScreenMixin` 新增 HUD 之后的挂点（隐藏界面时用 renderLevel 之后的挂点）；新增 `slashblade.BladeRenderStateRiftMixin`。

### 白闪导致的黑屏（2026-11-14 修正）

实测定格后和碎裂后各有一段黑屏，原因在白闪这一步的实现：白闪原本用叠加混合画一个不透明的灰色全屏方块，亮度随时间衰减。但原版 `position_color` 着色器的 JSON 自带混合设置，应用时会把混合方式改回普通透明混合，叠加没有生效，这个方块就成了盖住整个屏幕、由灰渐渐变黑的不透明方块：定格后约 40–52 tick 一段，碎裂后约 60–75 tick 一段（碎片被它盖住）。现在白闪改成白色加透明度、按普通透明混合画，衰减时是逐渐变透明。碎片描边同样改为透明度混合。之前为排查加的"定格图全黑就退回实时画面"的保护已移除。
