2026-11-18。前五版是调查与设计；第六版开始实装，实装记录与进游戏核对清单见第 13 节。同日第二版：写入已确认的 4 项决定，城堡改造改为世界生成时进行（6.2），新增城堡箱子方案（7.2）。第三版：其余问题全部确认（第 11 节），召唤仪式定在屋顶中央平台（7.3）。第四版：荆棘之地改为不设惩罚，不再另外分开城堡与荆棘之地（6.5）。第五版：酸雨附加缓慢和挖掘疲劳（6.6），荆棘可以手动破坏（6.7）。箱子内容、城堡敌人、掉落、召唤仪式与材料的详细设计另见[终焉城堡内容设计](终焉城堡内容设计-2026-11-18.md)。依据：实例中的暮色森林 1.20.1-4.3.2508（jar 内数据）与官方 `1.20.1` 分支源码、SlashBlade SenDims 1.1.4、整合包当前的 KubeJS 与任务。

称呼：**暮刃守卫**即「暮色剑守」（`slashblade_sendims:twilight_blade_warden`）；**米诺菇**是迷宫首领（流程里说的「牛头人」）；**余烬之灯**即烧荆棘的灯。

## 2. 原版进度机制（4.3.2508）

### 2.1 群系限制

- 数据驱动：`data/twilightforest/twilight/restrictions/<群系路径>.json`，条目 ID 就是群系 ID，可以给任何群系新增条目。字段：`advancements`（全部满足才解锁，不能为空）、`enforcement`、`multiplier`、可选 `structure_key`（刷提示怪时用哪个结构的提示书）、可选 `locked_biome_toast`（进入时提示框的图标）。
- 它是数据包注册表：只在开服时读取，`/reload` 不生效；登录时同步给客户端。
- 惩罚类型在代码里注册（`twilightforest:enforcement`），只有 5 种。服务端每 20 tick 检查一次玩家所在群系：

| enforcement | 效果 | 客户端天气 |
| --- | --- | --- |
| `darkness` | 每 3 秒给 10 秒黑暗，等级 = multiplier | 黑色气流 |
| `hunger` | 每 3 秒叠一层饥饿 | 蚊群 |
| `fire` | 每 3 秒点燃 multiplier 秒 | 灰烬 |
| `frost` | 每 3 秒给 5 秒霜冻，等级 = multiplier | 暴风雪 |
| `acid_rain` | 每秒 multiplier 点酸雨伤害 | 大雨 |

- 创造、旁观不受限；游戏规则 `tfEnforcedProgression` 关掉后全部失效。
- 天气画面按惩罚类型写死，自定义的惩罚类型没有天气画面。
- 群系是三维的：荆棘之地、终焉高原整列到基岩都是本群系；其他群系在地表以下若干格变成 `twilightforest:underground`，它没有限制。

### 2.2 结构锁

- 结构 JSON 的 `advancements_required`。只对暮色的「进度结构」生效：巫妖塔、迷宫、九头蛇巢穴、骑士要塞、黑暗之塔、雪怪洞穴、原版极光宫殿、巨魔洞穴、终焉城堡。**娜迦庭院没有结构锁。**
- 未解锁时，在结构包围盒内：
  - 不能破坏方块（`#twilightforest:progression_allow_breaking` 除外）；
  - 不能右键拉杆、按钮、箱子（`#forge:chests`）和反建筑者；
  - 玩家对敌对生物（Enemy）的攻击被取消，所以打不动首领；
  - 会刷带提示书的狗头人。
- 首领刷怪笼不看结构锁：玩家走近照样刷出首领，只是打不动。

### 2.5 写死在代码里的检查

- **奖杯基座**（`TrophyPedestalBlock.isPlayerEligible`）写死 `progress_lich`：16 格内没有带这个成就的玩家，放上奖杯也不会撤掉要塞护盾，骑士要塞进不去。新流程里骑士在巫妖之前，必须改。
- 极光砖在有 `progress_glacier` 时挖得快，和流程无关。
- 传送门落点（`TFTeleporter`）避开地标中心 5 区块内和未解锁群系。SenDims 的 `TFTeleporterMixin` 已经改了其中的 `isSafeAround`、`findPortalCoords`（按地表高度判断群系）。

### 2.6 地理

按群系层算法推算，需进游戏核对：

- 群系层的基础像素是 256×256 格。每 1024×1024 格放一个关键群系，四种（极光冰川、火焰沼泽、黑暗森林腹地、终焉高原）在每 2048×2048 格里各出现一次。任意位置 1500 格内大致有一座终焉城堡。
- 终焉高原约 256×256 格；外面一圈约 64 格厚的荆棘之地；荆棘高地是高原上下左右四块 256×256（十字形）。荆棘之地的四个角直接挨着普通群系。
- 巨魔洞穴是高地上的地标，每块高地大致一个。云上城堡（巨人矿工、武装巨人）是巨魔洞穴结构的一部分，在洞穴正上方。巨魔宝库包在巨型黑曜石里，要用巨人镐挖开。
- 城堡主厅 48×40×48，位于地标中心。

### 2.8 终焉城堡现状

4.3 里城堡是半成品：

- 没有箱子。
- 刷怪表全空：结构 JSON 的 `labelled_monster_spawns` 0～3 和 `spawn_overrides` 都是空的。分组：主厅 1、地牢 2、锻造间 3、屋顶凉亭 -1（不刷怪），其余部件 0。
- 五色力场挖不掉。城堡门（粉、蓝、黄、紫）右键就会消失，代码里的上锁判断是空的，永远能开。
- 屋顶的首领凉亭是 21×12×21 的紫色力场笼子，是原版预留的最终首领位置。里面有 4 行浮空文字：「Final Castle WIP.」和 Discord 地址。
- 还有 3 块占位告示牌：大塔「Parkour area 1 / Unique monster?」、钟楼「Parkour area 2 / mini-boss 1」、地牢底层锻造间「Mini-boss 2 / Gives talisman」。
- 地牢两层，每层由若干 31×7×31 的房间组成，中央是力场笼子；底层下面是 51×31×51 的锻造间。
- 损毁塔、残塔里长满荆棘。
- 城堡的信徒、噩兆立方、Roving Cube 掉落表都是空的。

### 2.9 传送门

- 暮色维度坐标比例 0.125：主世界 1 格 = 暮色 8 格。SkyblockBuilder 岛间距 2048 格，在暮色里各队相隔 16384 格，所以各队会对应各自最近的城堡。
- 进门时先在 200 格内找已有的门，找不到再做安全检查（群系、地标）后建新门。返程链接按「门所在的列」全局记录，不分玩家。

### 2.10 整合包现状

- 暮刃守卫：实体、AI、渲染已完成；没有掉落表、没有召唤方式；属性在 `enemy_attributes_mobs.js`（bossType1）；继承 Monster，算敌对生物，会受结构锁影响。
- 仪式框架：`custom_spawn/spawn_struct_base.js` 的 `registerStructure`，3×3×3 图样 + 激活物，支持 `precheck`、特效主题，`executeCommands` 里召唤。
- 任务：`config/ftbquests/quests/chapters/twilightforest.snbt`（[III] 暮色秘境）按原版顺序依赖 `progress_*`。
- 神化：`s2_twilight_bosses.js` 的暮色首领词条已经包含信徒和噩兆立方。
- 暮色相关的 mixin：SenDims 有 `TFTeleporterMixin`、`LichMixin`；bossrefactortf 改了各首领的战斗。
- 极光宫殿数据包已经在 `kubejs/data` 里，见第 9 节。

### 6.5 城堡伸进荆棘之地

**问题**：终焉高原约 256×256，主厅在正中，但城堡的其他部件会伸出去：

- 黄色迷宫先向东伸出约 60 格，再绕回西北的入口塔；
- 蓝色迷宫先向西伸出约 60 格，再绕到东南的钟楼；
- 迷宫上的死路还挂着损毁塔、残塔；
- 地牢每层从入口房向外扩 2～3 间 31×31 的房间。

按代码估算，城堡离中心最远可以超过 100 格；高原边缘还会被群系层的缩放抖动削进去一些。所以城堡有一部分会落在荆棘之地里（整列到基岩，地牢里也一样）。

**已确认的处理**：荆棘之地不设惩罚（第 4 节），不另外把城堡和荆棘之地分开。城堡伸进荆棘之地的部分不会挨酸雨。没拿灯就出城的玩家进入荆棘高地后照样挨酸雨（原版每秒 0.5 点，想更明显可以调高 `multiplier`）。

**剩下的风险：荆棘长进城堡**

- 荆棘之地的荆棘按区块铺：每个区块约 70% 的列，从世界生成高度图的顶面往上长，只往空气和树叶里长，离地形超过 64 格就不长。
- 这个摆放规则不避让地标（大部分暮色地物会避开地标周围），而高度图在放完结构之后已经包含城堡方块。
- 所以落在荆棘之地的桥面、塔顶、塔窗附近可能长出荆棘，挡住黄色、蓝色路线。钥匙箱是拿灯之前就要拿到的，路线被挡就卡关。
- 损毁塔、残塔里的荆棘是城堡自带的，不算在内，那两种塔本来就是藏奖励的地方。

**处理**：荆棘改成可以手动破坏（6.7），挡路时玩家自己拆，不再需要限制荆棘的生成。实装后进游戏看几座城堡（`/locate structure twilightforest:final_castle`），确认外围荆棘的多少不影响体验即可。

### 6.6 酸雨附加缓慢和挖掘疲劳

已确认：酸雨惩罚同时给缓慢和挖掘疲劳。

- **做法**：SenDims mixin `Enforcement.enforceBiomeProgression`。暮色每 20 tick 对玩家调用一次这个方法，调用前已经排除了创造、旁观和关掉进度限制的情况。在里面取当前生效的限制，惩罚类型是 `twilightforest:acid_rain` 时，额外给缓慢和挖掘疲劳。
- **为什么不新建惩罚类型**：客户端的酸雨画面是按 `acid_rain` 这个 ID 写死的，沿用原 ID 才能保留大雨画面。
- **范围**：按第 4 节的新表，用酸雨的只剩荆棘高地（终焉高原、荆棘之地都改成了不触发），所以实际只在没拿灯时进高地生效。
- **数值**：建议默认缓慢 II、挖掘疲劳 II，持续 5 秒，每秒刷新，离开高地后几秒内消失。等级和时长写进 SenDims 配置，进游戏再调。

### 6.7 荆棘可以手动破坏

已确认：荆棘没那么硬，挡住城堡里的东西时玩家可以自己拆。

原版荆棘（棕色、绿色）的硬度是 50（同黑曜石），而且被玩家破坏时不会真的被拆掉，反而会再长出一簇新荆棘，所以实际上拆不掉。碰到会扣血，没有掉落。改动：

| 改动 | 做法 |
| --- | --- |
| 拆了不再长新荆棘，正常破坏 | SenDims mixin `ThornsBlock.onDestroyedByPlayer` |
| 硬度降到 2～4（建议 3），抗爆保持原样 | KubeJS 启动脚本 `BlockEvents.modification` 改 `destroySpeed`。这个版本的 KubeJS 如果改不动，就放进上面同一个 mixin |
| 斧子挖得快 | 加进 `#minecraft:mineable/axe`（`server_scripts/block_tags.js`） |

碰到扣血、没有掉落、余烬之灯一次烧掉一大片，这些不变。

**影响**：荆棘之地手工也能挖穿，灯从「唯一通路」变成「方便的工具」。拿灯之前出城，靠的是高地的酸雨、缓慢、挖掘疲劳，以及巨魔洞穴（含云上城堡）的结构锁：没灯的人进去拆不了方块、打不动怪、开不了箱子。

如果只想让城堡里的荆棘能拆、外面的荆棘之地仍要用灯烧，可以在同一个 mixin 里按「离城堡中心的距离」判断，不改全局硬度。

- 地牢房间中央 17×17 是一圈力场围起来的笼子：绿、蓝力场的进不去，只有入口房和出口房的粉色笼子有门。能走的是笼子外面一圈。

### 13.7 进游戏核对

新建世界（或重置暮色）后：

1. 进暮色：落在最近城堡主厅的传送门旁；从这个门回主世界回到原来的门。
2. 城堡：补给箱、塔楼箱、地牢箱、四色钥匙箱和四个钥匙守卫是否都生成，守卫是否是 Leader；损坏塔楼的箱子会不会被荆棘盖住；屋顶力场有没有堵住角塔。
3. 仪式：屋顶中心能否搭成并召唤暮刃守卫；屋顶以外、已有守卫时是否拦下；守卫掉灯。
4. 灯烧荆棘；荆棘手动拆掉后不再长；高地酸雨附带缓慢和挖掘疲劳。
5. 成就链按新顺序推进；首领刷怪笼在前置成就之前不刷；奖杯基座在 `progress_naga` 之后可用。
6. 任务章节：主线逐个点亮；完成米诺菇任务不再给迷宫破坏者；以太章节的变量卡任务在暮色终章后可完成。
7. 提示书：没有灯进巨魔洞穴、没有迷宫破坏者进迷宫、没打恶魂进巫妖塔时，拿到的是改写后的文字。
8. 终焉符文核心的亮度（KubeJS `lightLevel` 的刻度）。
