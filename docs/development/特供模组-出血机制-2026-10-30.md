# 特供模组中的出血机制

> 本文记录 2026-10-30 调整前的机制。当前已改为整数生命值上限、200% 攻击力累积与 15% 已损生命爆发，见[调整后的规则及更新说明](特供模组-出血调整-2026-10-30.md)。下文的 120、30/45、20% 等数值只用于对照历史实现。

核对对象：用户指定的 `MixinBloodAccumulationEvent.java`、当前安装的 `slashblade_sendims-1.1.1.jar`、`lethal_slash_project-1.1.0.jar` 与 SlashBlade 1.9.65。已安装 JAR 中的实现与所给源码一致；最新调试日志确认该 Mixin 已应用。

## 累积的来源

计量表存储在受击生物的 `BLOOD_ACCUMULATION_CAPABILITY` 中，所有有此能力的生物都可以累积。不同攻击者对同一目标共用计量表，最后一次增加累积的攻击者 UUID 会覆盖此前记录。

`slashblade:bleeding_cutting` 由 Lethal Slash Project 注册。它响应拔刀剑 `HitEvent`：

- 刀必须带有该特效，攻击者必须是玩家，玩家当前经验等级至少 20；不消耗等级。
- 刀内骄魂量 **大于 2000** 时，每次事件增加 45；2000 及以下增加 30。
- 没有额外随机概率，也不按本次刀伤的多少换算累积量。
- 增加累积前将目标的 `invulnerableTime` 设为 0，并保存此次攻击者 UUID。

另一个来源是 `slashblade:dual_blade_main`：触发攻击的刀带主特效，副手为带 `slashblade:dual_blade_off` 的拔刀剑时，普通增加 30；攻击者有力量效果时增加 45。该处理函数没有额外调用经验等级检查。若与 `bleeding_cutting` 同时满足，会在同一个事件中分别加值。

## 触发与自然衰减

特供 Mixin 在原 `onLivingTick` 开头接管处理，并取消原方法。只在服务端计算：

```java
accumulation >= 120 && entity.invulnerableTime == 0
```

因此达到 120 不一定立即结算：必须碰到一次受伤无敌时间为零的生物更新。未能触发时仍会继续衰减。

每逢 `entity.tickCount % 5 == 0`，若累积量大于零就减 1。正常 20 TPS 下相当于每秒减 4，战斗中也会衰减；只有生物更新时才处理。

不计衰减时，30 点一次需要 4 次，45 点一次需要 3 次。实际 30 点的第四次可能因自然衰减未满 120，必须再命中。触发后整条计量表清零，超出 120 的部分不保留，也不会按倍数多次结算。

## 爆发伤害

先读取该次触发时的最大生命值和当前生命值，计算一次：

```text
总基础伤害 D = 8 + 0.2 × (最大生命值 − 当前生命值)
```

这是已损失生命值的 20%，不是最大生命值的 20%；公式没有读取刀的攻击力。

| 最大生命 / 当前生命 | 本次总基础伤害 | 每段基础伤害 |
| --- | --- | --- |
| 100 / 100 | 8 | 2 |
| 100 / 50 | 18 | 4.5 |
| 100 / 20 | 24 | 6 |
| 1000 / 100 | 188 | 47 |

同一更新内连续调用四次 `entity.hurt(source, D / 4)`。每次调用后都将目标的 `invulnerableTime` 清零，包括最后一次。四段使用同一个预先算好的 D，不会随着前几段扣血在本轮中继续提高。

四次调用都是普通的 `mobAttack` 伤害：

- 在目标当前服务端维度中按 UUID 查找最后一次累积者；若找到活体实体，使用它作为伤害来源。
- 找不到时，以目标自身作为 `mobAttack` 来源。
- 不是直接扣血或绕甲伤害，会经过通常的受伤事件、护甲、附魔、抗性、吸收、格挡以及其他模组规则。
- 分成四次后，每段分别经过减伤，最终损血不保证等于 D，也不保证等于一次 D 大小攻击的结果。
- 整合包针对玩家的受伤倍率和玩家来源伤害缩放也可能参与这四次结算。
- 源码不检查 `hurt` 的返回结果；即使因格挡或特殊免疫未成功扣血，仍会继续后续调用、播放粒子并清空计量表。

清零无敌时间能绕过常规的受伤间隔，但不能保证穿透生物自身的特殊无敌机制。

## 粒子、清零与当前提示问题

爆发时生成两组深红色尘埃粒子：主体数量 `min(累积量 / 5, 60)`，另加脚下附近 20 个；这两组粒子不额外造成伤害。之后清空累积量与最后攻击者 UUID。

当前 `kubejs/assets/kubejs/lang/zh_cn.json` 的描述仍写着“达到30时按目标生命值与刀伤害结算出血伤害”。实际生效的是 **120 阈值、已损生命比例、四段普通物理伤害**，该描述已经与代码不一致。本次调查没有修改这条文案或出血逻辑。
