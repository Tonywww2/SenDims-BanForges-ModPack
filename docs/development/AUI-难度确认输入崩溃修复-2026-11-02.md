# AUI 难度确认输入崩溃

崩溃报告：`crash-reports/crash-2026-11-02_17.39.43-client.txt`。

异常为 `StringIndexOutOfBoundsException: Range [0, 3) out of bounds for length 0`，首个业务栈位于 ApricityUI 1.2.7 的 `AbstractText.insertText(AbstractText.java:353)`，由字符输入事件触发。

## 原因

难度确认界面复用一个输入框，之前切换弹窗和关闭弹窗时仅执行 `input.value = ''`。AUI 的 `value` 是可直接写入的 Java 字段；赋值不会自动同步光标、选区、选择锚点或撤销记录。

典型复现：N+18 第三个确认框输入 `Yes`，光标位置为 3；进入第四框后文本长度变成 0，光标仍为 3。接着输入 `Confirmed` 的第一个字符时，原生 `insertText()` 调用 `value.substring(0, cursor)`，即对空串取 `[0,3)`，与本次崩溃一致。取消后重新打开也可能触发。

已从当前安装 JAR 核对：`Element.setAttribute('value', ...)` 在用户编辑后受 `valueDirty` 控制，不保证更新实际值；`AbstractText.setAttribute()` 随后会清理光标、选区、撤销历史。因此不能仅把原来的字段赋值换成属性赋值。

## 修复

在 `kubejs/assets/apricityui/apricity/screens/difficulty.html` 添加共用重置函数，切换和关闭弹窗均调用：

1. `input.value = ''`，确保当前实际文本为空。
2. `input.setAttribute('value', '')`，调用 AUI 原生同步逻辑，清理选区、撤销历史并刷新渲染缓存。
3. 调用可用的 `setSelectionRange(0, 0)`，明确将光标、选区和锚点归零。

保持既有四级确认流程、大小写不敏感匹配、提交命令、阈值和战斗数值。运行时只修改这一份 HTML，没有新增类补丁或修改 AUI JAR。
