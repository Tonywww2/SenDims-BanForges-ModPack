## 瓶颈二　刷怪过程进入深四地形查询

### 调用位置与证据

采样中的深四 `worldgen` 调用子树并集为 1336 ms，约占服务端主线程样本的 8.92%。该计算消除了同一子树内重载、嵌套调用的重复累计。

主要调用链如下。

```text
ServerLevel tick
  ServerChunkCache tick
    NaturalSpawner
      刷怪位置与高度检查
        SpiralChunkGenerator.getBaseHeight
          TerrainProfile.sample
            TerrainProfile.raw / calculate
              BaseTerrain.shape / calculateShape
                NaturalRelief.sample / AridRelief.sample
                SeededNoise
```

`SpiralChunkGenerator.getBaseHeight` 在采样中显示为运行时混淆名 `m_223133_`。两条主要分支分别为 888 ms 和 412 ms，累计 1300 ms，约占线程样本的 8.68%。这说明地形相关成本直接出现在自然刷怪的运行期调用中。

| 方法 | 主要分支的包含时间合计 | 主线程样本占比 |
| --- | ---: | ---: |
| `SpiralChunkGenerator.getBaseHeight` | 1300 ms | 8.68% |
| `TerrainProfile.calculate` | 1168 ms | 7.80% |
| `BaseTerrain.shape` | 928 ms | 6.20% |
| `BaseTerrain.calculateShape` | 880 ms | 5.88% |
| `NaturalRelief.sample` | 388 ms | 2.59% |

以上方法互相嵌套，不能累加。`TerrainProfile.sample` 有重载和包装层，按方法名称直接累计会把同一时间重复计入。此前简单汇总得到的约 16.5% 属于这种重复累计，交接归因采用子树并集的 8.92%。
