# SDBF UTF 与 C2MEF 迁移及三组验证设计

2026-11-09，设计稿 v1。

## 范围与边界

面向新存档，设计 Tectonic 到 UTF 的替换、整合包适配和三组实际验证。SLO 1.0.11 已加入，作为三组共同条件。本阶段产物为方案、参数候选与静态核对记录。

高度采用此前讨论的 `worldHeight=320`、`worldDepth=64`。有效建造范围为 Y=-64～319，320 为上边界，共 384 层。

本方案以本整合包的数据包、SkyblockBuilder 开局、RU／Terralith 群系和阶段维度为兼容对象。候选参数需要在后续实际测试后定稿。

## 一、Tectonic 清理与资源依赖处理

### 1. 清理清单

后续实施时从发布目录和安装清单移除 Tectonic JAR 与 `config/tectonic.json`。同时检查启动参数、模组清单、服务器打包脚本和自动复制规则，清除它们对旧文件的部署引用。

检查当前启用的独立数据包、资源包内数据、KubeJS 数据及模组内数据。验收时，新的有效资源图应能完整解析，所有必需的注册表引用都有提供者。

静态扫描当前 KubeJS／配置文本，以及 Tectonic JAR 以外的模组和数据包 JSON 资源，尚未发现外部 `tectonic` 文本引用。扫描结果保存在 `docs/archive/chunk-performance-2026-11-07/terrain-replacements/tectonic-reference-audit.json`。实施时仍需对最终发布文件集重新扫描，并检查启用资源的运行时来源。

### 2. 发现引用时的处理规则

| 引用类别 | 处理方式 |
| --- | --- |
| Tectonic 自带或 Terratonic 叠加资源 | 随对应模组资源提供者一并退出发布集 |
| 主世界噪声设置指向 Tectonic | 切换到本方案生成并验证的 UTF 主世界设置 |
| 自定义维度密度图引用 Tectonic | 逐项识别地形含义，使用原版或 UTF 的对应计算重建依赖图 |
| 条件加载的 Tectonic 兼容补丁 | 检查补丁目的，改写为 UTF 对应条件和行为，或移除已失去作用的补丁 |
| 标签中的可选 Tectonic 条目 | 清理对应条目，保留同标签中的其他生成资格 |
| 导出的旧噪声快照或缓存包 | 从新档初始化和发布复制清单中清理，并重新生成资源清单 |

密度函数迁移按计算语义匹配，所有替换都记录原 ID、目标 ID 和生成效果。发布清单附带删除文件列表，避免覆盖式更新留下旧 JAR 或旧配置。

## 二、UTF 的整合方式

### 1. SkyblockBuilder 继续作为新世界入口

主方案继续使用 `skyblockbuilder:skyblock` 创建新档，由 SkyblockBuilder 管理出生岛、团队、回岛和相关开局行为。当前 `Overworld.Default=true` 的分支会构造原版 `NoiseBasedChunkGenerator`，读取 `minecraft:overworld` 群系参数和噪声设置。该行为已通过当前 JAR 字节码核对。

将选定 UTF 预设导出为经过资源筛选的整合包数据，通过 KubeJS 数据资源在注册表加载时提供主世界噪声、UTF 密度函数和关联设置。客户端和专用服务端共用这份生成定义。

UTF 自带的服务端自动导出逻辑以 `level-type=ultraterraforged:ultraterraforged` 为触发条件，因此本方案需要在发布前完成导出与打包。UTF 的预设文件负责参数编辑，导出的数据负责实际世界生成。二者用版本号和内容哈希建立对应关系。[UTF 预设与服务端说明](https://github.com/Pandaismyname1/ultraterraforged/blob/1.20.1/README.md)

新档烟雾测试必须确认生效的密度函数引用 UTF 资源，运行时 `GeneratorContext` 可取得正确预设，实际高度范围为 -64～319。生成器类名、运行时预设与资源提供者共同作为判定依据。

建议文件职责如下，属于后续实施清单。

| 文件或目录 | 职责 |
| --- | --- |
| `config/ultraterraforged/modpack-presets/SDBF_Continental.json` | UTF 参数源文件 |
| `config/ultraterraforged/modpack.json` | 指定该预设，`useAsDefaultWorldType=false` |
| `kubejs/data/` 中经筛选的 UTF 导出资源 | 实际注册表数据及整合包兼容覆盖 |
| `config/defaultworldtype/client-config.toml` | SkyblockBuilder 默认入口和世界类型白名单 |
| `kubejs/data/minecraft/worldgen/world_preset/normal.json` | 与 SkyblockBuilder 入口共同验收 |
| 服务端 `server.properties` | 使用同一 SkyblockBuilder 世界类型 |
| 导出清单与参数哈希 | 追踪源预设和实际加载资源的一致性 |

正式世界选择界面以整合包批准的入口为准。参数开发与世界类型编辑器属于制作流程，导出后使用固定生成定义进行评测。

### 2. 出生岛验收

当前出生高度 Y=300，主模板高 11 格，理论包围盒可落在 Y=300～310。需要结合实际偏移、出生点和方块放置行为验证。

- 单人与专用服务端的新档均能生成完整出生岛。
- 新队伍建岛、第二座岛、重进、回岛、死亡重生和保护区域均可用。
- 出生点上方有足够空间，模板顶部及附属结构不触及 Y=319。
- 调参后的地形、植被与自然结构不侵入出生岛有效范围。
- 检查 `classic_moss`、`small_flat`、`otto` 等已配置模板。

高度验收采用多种子搜索与模板实际包围盒，重点检查出生岛所在位置和建岛候选位置。

### 3. 导出资源的兼容策略

前期 UTF 导出包中除了主世界噪声，还包含原版树木、圆盘地物、石质矿脉及洞穴 carver 的覆盖。它们可能与现有数据包或其他维度共用资源发生交集。

实施时先建立导出资源与现有资源的冲突表，按下面的策略整理。

| 资源类别 | 主方案 |
| --- | --- |
| 主世界噪声与维度类型 | 使用固定 320 上限的 UTF 生成定义 |
| UTF 核心 preset、noise、density_function、surface 等 | 按引用闭包完整打包，核对注册表缺失与资源优先级 |
| 原版树木及植被覆盖 | 首轮候选设 `customBiomeFeatures=false`，沿用群系自身植被体系，并筛除无用途的全局树木覆盖 |
| 原版岩石矿脉、泥土／砂砾圆盘覆盖 | 逐项合并现有整合包定义；与阶段资源和配方依赖一起验收 |
| 原版 cave／canyon carver 全局覆盖 | 首轮以现有共享定义为基础，主世界深洞增强优先使用 UTF 上下文限定的洞穴功能 |
| 方块替换标签 | 采用合并规则，核对新增石材与整合包矿物、洞穴替换标签的关系 |
| UTF 群系修改器与新增地物 | 检查目标群系和执行维度，核对共享群系在其他维度的行为 |

如某个主世界专用资源需要新的 ID，将其连同所有引用一起迁入 `sdbf:utf/…` 命名空间。共享群系上的地物如需维度限定，优先利用现有条件入口；必要的定点兼容处理列入单独补丁与测试记录。

静态删除导出资源前必须完成引用检查。导出包中的预设声明和实际保留资源保持一致，避免参数显示已启用而有效资源仍指向另一套实现。

原版树木、共享 carver 和矿脉中由整合包接管的项目，写入预设说明与导出策略清单。参数验证器按该清单检查实际生效项。

### 4. 多维度绑定

`minecraft:the_overworld` 也读取 `minecraft:overworld` 噪声设置，设计中将其归入 UTF 主世界地形体系。其他维度按其当前定义单独核对。

重点验证 `sdbf:deep_realm_level_1`、`sdbf:deep_realm_level_2`、`sdbf:inside_the_end`、`sdbf:asteroid_belt`、深四、午夜、Aether、Undergarden、SGJourney 与 Ad Astra／土卫六等维度。

每个维度记录生成器类型、噪声设置、群系源、维度高度，以及启用 UTF 上下文的实际情况。共享的原版密度函数、carver、地物和标签均纳入依赖检查。验收包含该维度的阶段资源及关键结构。

## 三、UTF 风格参数候选

目标为更清晰的大陆与海洋轮廓、更宽的地形单元和河谷、更丰富的可探索地下空间。首版通过大陆尺度、地形水平尺度和水系组织取得宽阔感。

以下数值为 v1 候选，默认值取自已测试的 UTF 1.0.3 预设。参数名称已按该版本代码和预设核对，最终值依后续地图统计与实景对照收敛。

### 1. 固定高度与宏观布局

| 参数路径 | 默认值 | v1 候选 | 目的 |
| --- | ---: | ---: | --- |
| `world.properties.worldHeight` | 512 | 320 | 与本包现有高度边界对应 |
| `world.properties.worldDepth` | 64 | 64 | 下界限为 -64 |
| `world.properties.seaLevel` | 63 | 63 | 为既有海洋、沿海结构和资源提供统一基准 |
| `world.continent.continentScale` | 3000 | 4800 | 放大陆地与海洋单元 |
| `world.continent.continentSizeVariance` | 0.25 | 0.20 | 收敛大陆尺度差异，改善整体可读性 |
| `world.continent.continentSkipping` | 0.25 | 0.20 | 降低大片陆地单元被跳过的概率，配合海洋比例复核 |
| `terrain.general.terrainRegionSize` | 1200 | 1600 | 延长同类地貌的连续范围 |
| `terrain.general.globalHorizontalScale` | 1.0 | 1.25 | 扩展地形水平跨度 |
| `terrain.mountains.horizontalScale` | 1.0 | 1.15 | 宽阔山脊与山坡 |
| `terrain.hills.horizontalScale` | 1.0 | 1.10 | 拉长丘陵起伏 |
| `climate.biomeShape.biomeSize` | 225 | 300 | 形成更连续的群系景观 |
| `climate.biomeShape.biomeWarpStrength` | 80 | 60 | 减少群系边界的细碎扭曲 |

全局与局部水平尺度会叠加，本候选的山地尺度约为默认的 1.44 倍。大陆类型以当前 `MULTI_IMPROVED` 为起点。海陆比例和岸线控制点在首轮地图统计后微调，以连通陆地、大洋尺度和海岸复杂度共同评价。

首轮地图目标为可辨认的大型陆块与连续海域。候选海洋面积占比先以 30%～45% 为调参区间，统计范围覆盖多个大陆尺度，并同时检查陆地连通性。该区间属于视觉设计目标。

| --- | ---: | ---: | --- |
| `rivers.riverCount` | 8 | 10 | 为放大的大陆提供主干水系 |
| `rivers.mainRivers.bedWidth` | 8 | 10 | 增强主河道尺度 |
| `rivers.mainRivers.bankWidth` | 20 | 26 | 更宽阔的河谷／河岸过渡 |
| `rivers.branchRivers.bedWidth` | 5 | 6 | 支流与主干尺度协调 |
| `rivers.branchRivers.bankWidth` | 14 | 18 | 减少细窄裂缝式水道观感 |
| `rivers.gorgeDepth` | 32 | 24 | 收敛过深的河谷切割 |
| `rivers.lakes.chance` | 0.30 | 0.24 | 调整湖泊出现密度 |
| `rivers.lakes.sizeMin` / `sizeMax` | 75 / 150 | 100 / 200 | 形成较少、较完整的湖泊单元 |
| `coasts.coastalIslands.frequency` | 0.50 | 0.30 | 减少岸边碎岛 |
| `coasts.peninsulas.frequency` / `size` | 0.50 / 1.0 | 0.40 / 1.25 | 较大的半岛与海湾 |
| `coasts.skerries.density` | 0.50 | 0.30 | 收敛海面碎礁密度 |
| `coasts.islandArcs.frequency` | 0.30 | 0.20 | 调整海岛链出现密度 |
| `landforms.atolls.frequency` | 0.35 | 0.25 | 为主海岸轮廓留出更大连续空间 |
| `oceans.shelves.width` | 1.0 | 1.25 | 更明确的大陆架过渡 |

河流随地形蜿蜒、高位河流与瀑布作为 UTF 的特色参与实景评价。检查河网连续性、湖面悬空、水体墙、河口台阶、海岸方块突变以及船只可通行性。

侵蚀预算以当前 `dropletsPerChunk=135`、`dropletLifetime=12` 为首轮基准。水平尺度和地貌分区先完成视觉收敛，额外侵蚀成本通过独立剖析评估。

### 3. 深洞与地下群系

| 参数路径 | 默认值 | v1 候选 | 目的 |
| --- | ---: | ---: | --- |
| `caveFeatures.giantCaverns.frequency` | 0.30 | 0.42 | 增加可探索的大型地下空间 |
| `caveFeatures.layerCaves.frequency` | 0.40 | 0.50 | 增加层状通道与横向空间 |
| `caveFeatures.undergroundRivers.frequency` | 0.40 | 0.48 | 增强地下水系联系 |
| `caveFeatures.karstCaves.size` | 1.0 | 1.15 | 扩大岩溶洞穴单元 |

原有 cheese、spaghetti、noodle 三类概率已经为 1。后续增强以洞穴体积、形态、连通性和地下群系分配共同实现。

几何洞穴密度和地下群系覆盖率分开测量。标签负责结构与地物的生成资格，地下群系的出现由群系源气候参数及区域分配决定。

RU 当前区域权重为 11／8／1，其主、次区域配置列出了原版三种地下群系和 RU 五种地下群系，`toggle_custom_regions=false`。首轮使用该分布建立参照，再根据采样调整地下分配。若现有区域配置不足以实现目标，采用主世界限定的 TerraBlender 气候参数补充入口，实施前明确代码入口和数据边界。

地下群系的设计目标包括：

- RU 五种地下群系均具备实际可达性，重点检查 `ancient_delta` 和 `prismachasm`。
- Terralith、YUNG、DarkerDepths 和原版地下群系能实际出现并带有对应地物。
- 在可通行洞穴邻接采样中，特色地下群系覆盖率尝试达到旧配置的 1.25～1.5 倍。
- 深层矿物、古城、地下结构与阶段资源有可达位置，洞穴之间具备足够连接。
- 同时记录空腔率、含水空腔率和矿物单位区块产量，结合战斗与采集阶段验收。

地下气候补充的具体参数，以实测缺口和安装版本的区域实现确定，属于设计中的待测项。

## 四、C2MEF 集成与 HotAI 策略

### 1. 候选版本

使用用户指定项目的 `c2meforge-0.2.0-forge.9.9.6-all.jar` 作为首个候选，CurseForge 文件 ID 为 9387498。发布 JAR 声明 Forge 47+，其加载器约束覆盖当前 47.4.10。检查得到的 SHA-256 为 `e73681883b2c867049800f8b2f7bdcbbbda6c9a44eb5e165c0513914364abfc6`。[候选发布页](https://www.curseforge.com/minecraft/mc-mods/concurrent-chunk-management-engine-forge/files/9387498)

该项目声明包含 SkyblockBuilder 等模组的线程安全适配，并支持常见 Forge 性能模组。后续以候选 JAR 的实际加载日志、模块启用结果和整合包测试确认覆盖情况。[项目说明](https://www.curseforge.com/minecraft/mc-mods/concurrent-chunk-management-engine-forge)

### 2. 配置及重叠检查

- 将现有 `c2me.toml` 与候选版本生成的配置逐项对照，保存有效值和兼容性自动禁用原因。
- `gcFreeChunkSerializer` 首轮明确设为 false。当前配置已记载 Architectury 9.2.14 的兼容限制，保存／读取测试重点覆盖 Forge 区块附加 NBT 和方块实体。
- 多线程生成、异步区块管理和 I/O 为候选的主要评估对象，记录实际生效模块。
- 公平测试配置统一实际渲染／模拟距离，C2MEF 的 no-tick 扩展视距单独列为功能测试。
- 先评估自动并行度，再对 4／6／8 等有限并行度进行敏感性测试，结合吞吐、峰值内存和探索延迟选定正式值。
- 对 UTF 自有线程池与 C2MEF 并行度一起采样。UTF 1.0.3 的 `PerformanceConfig.read` 当前直接返回默认值，线程配置文件的有效性需要代码级核对。
- 逐项核对 FastNoise、ModernFix、Radium、Starlight／StarlightxAE、Lithostitched、SLO、TerraBlenderFix 以及既有 HotAI 的重叠注入与生效状态。
- 自定义生成器重点检查深一、深二、深四、小行星带和里末地的共享随机数、缓存和跨区块访问。

### 3. HotAI 修复流程

出现问题时保存完整日志、线程转储、JFR、最小复现种子、坐标和有效模块列表。先用模块开关二分区分生成、地物、照明、I/O 或序列化路径，再定位负责的类与共享状态。

HotAI 补丁采用对应 JAR 哈希和类签名作为版本边界，优先修复具体的共享可变对象、随机数使用、跨区块访问顺序或维度判定。涉及串行化时，将锁限制在有问题的模组或阶段，评估补丁后的实际并行收益。

每个补丁附带可复现用例、生成一致性检查、保存重开检查和性能回归数据。补丁介入后重新跑受影响的正式对照；若补丁具有跨组影响，将同一修复纳入各组共同条件。

加载失败、区块长期等待、线程死锁、错误地形、光照错误、资源缺失、保存数据丢失和不可解释的生成差异均进入问题清单。候选是否达到可发布状态，以这些问题的复测结果判定。

## 五、三组正式对照

| 分组 | 地形方案 | 并发区块引擎 | SLO |
| --- | --- | --- | --- |

A/B 用于比较整套地形方案的实际成本与景观变化。B/C 还需比较同坐标的逻辑内容，确认并发引擎对生成和保存的一致性。

### 1. 固定条件

- 三组分别从相同的整合包快照复制，记录 JAR、配置、脚本、数据包和补丁哈希。
- 使用新档，固定种子 `20261107`、`1111`、`2222`，主要吞吐测试每种配置至少三次独立运行。
- 统一 Java、Forge、堆大小、GC、渲染距离、模拟距离及测试机器电源状态，记录后台负载。
- 单人和专用服务端分开运行，启动、配方注册、预热、生成、保存与重开分别计时。
- 固定坐标与按地貌匹配的路线共同使用，海洋、森林、山地和大结构分别统计。

已有约 192 次请求的小范围测试用于流程校验和历史参考。正式结论使用新的共同基准，包含已经加入的 SLO 和本次定稿参数。

### 2. 工作负载

| 阶段 | 工作负载 | 主要输出 |
| --- | --- | --- |
| 创建与开局 | 新建世界、出生岛、队伍建岛、重生和回岛 | 功能检查、启动时间、资源来源 |
| 小范围生成 | 预热后固定三片区域的同步 FULL 请求 | 单次延迟、调用链、快速回归 |
| 持续吞吐 | Chunky 半径1000，约16,129个区块 | FULL 区块／秒、总时间、CPU、分阶段成本 |
| 探索载图 | 固定速度和路线的客户端探索，含陆地与海岸 | 帧时间、载图延迟、MSPT、待处理队列 |
| 结构压力 | 主世界大型城堡、地底结构、带 DHD 星门等 | 结构生成与放置耗时、完整性 |
| 多维度 | 代表性阶段维度的新区块与关键资源 | 生成器绑定、群系与结构核对 |
| 长时间运行 | 探索—返回—卸载—空闲循环60～90分钟 | 存活堆、原生内存、缓存和卸载表现 |
| 保存与重开 | 正常保存退出、重新加载同一批区块 | 数据一致性、I/O、重开耗时 |

探索负载优先使用实际客户端连接专用服务端。需要扩展并发探索压力时，可增加独立区块请求路线，同时在报告中区分模拟请求和真实客户端网络负载。

### 3. 性能指标

报告总耗时、FULL 区块吞吐、请求延迟中位数／P95／P99／最大值、MSPT、客户端帧时间、CPU 占用和 I/O。JFR 线程选择覆盖 Server thread、Worker、UTF 自有线程及 C2MEF 执行器。

地形、群系、地物、结构、照明、I/O 和调度分别归因。父子调用链的采样占比按层级解释。记录队列长度和完成时刻，确认计时终点对应所需区块全部完成。

### 4. 内存指标

记录堆峰值、分配速率、GC 暂停、卸载后的存活堆、进程私有内存／工作集、原生内存分类、线程数与加载区块数。

长时间测试在相同工作负载循环后返回固定地点，释放测试区块票据，等待保存与卸载完成，再在统一空闲阶段采集 GC 后占用。主动 GC 和堆转储放在独立采样窗口。

C2MEF 的在途区块数量、UTF tile 缓存和实际持有区块数与内存曲线一并报告。持续上升时，在相同保留区块规模下对低／高占用阶段进行堆对象持有链比较。

### 5. 存储指标

三组生成相同数量、相同完成状态的区块，在正常退出保存后统计 region、entities、poi 和其他世界数据。

报告磁盘文件大小、MCA 已分配扇区、有效压缩 NBT 字节、每 FULL 区块字节、非空气区段数量、方块实体数量与结构体量。结合群系和实际内容解释 A/B 的存储差异。

B/C 同时校验已保存的逻辑方块、群系、结构、POI、方块实体和关键附加 NBT。排除字段采用明确清单，例如保存时间与自然生成实体 UUID；矿物、战利品种子、结构位置和配方相关状态纳入一致性检查。

先比较 B/B、C/C 的同种子独立重复，再解释 B/C 差异。任何无法说明来源的资源、结构或保存差异进入兼容性问题清单。

## 六、视觉测试设计

视觉取样覆盖三类尺度。

| 尺度 | 观察对象 |
| --- | --- |
| 宏观 | 大陆连通性、海陆比例、大洋宽度、岛链和海岸复杂度 |
| 中观 | 山系连续性、谷地宽度、河网、湖泊、森林边界和自然结构嵌入 |
| 地下 | 深层洞室、横向通道、地下水、特色群系、洞穴入口和关键地下结构 |

制作两套视图：相同坐标的世界对照，以及同类别地貌的匹配对照。匹配点的选择规则和坐标随报告提供。

采用固定分辨率、FOV、视距、时间、天气、相机位置和朝向。基础对照采用统一渲染设置，展示图另记录光影和资源包设置。

沿用用户要求的命令行工作流。后续使用测试专用客户端探针，在游戏主线程设置相机、等待区块及网格就绪，再调用游戏截图接口。探针与正式发布内容分别管理。截图按固定位置和稳定条件触发，避免将未完成的载图或网格状态作为最终画面。

宏观布局额外用生成数据绘制高度／海陆／群系图，与实景截图共同评价。图片测量和地形数据统计记录采用相同坐标基准。

视觉验收关注宽阔感、地貌连续性、海岸可读性、洞穴可探索性、群系辨识度和结构贴地情况。高度相关检查覆盖山顶、树冠、出生岛和高结构。

## 七、通过条件与交付物

### 通过条件

1. 新档注册表和数据包资源完整加载，所有计划保留的阶段维度具备正确生成器和资源。

6. 三组完成性能、内存、视觉和存储对照，结果包含重复次数与波动范围。
