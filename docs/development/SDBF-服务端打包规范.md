# SDBF 服务端打包规范

## 配置目录中的 YSM 文件夹

- 服务端打包时，不包含 `config/` 或 `configs/` 内属于 YSM（Yes Steve Model）的文件夹及其全部内容。
- 当前整合包明确排除 `config/yes_steve_model/`，包括其中的自定义模型、资源、缓存和其他子目录。
- 按目录实际归属识别 YSM 文件夹，不使用文件夹名称包含 `ysm` 的简单子串匹配，以免误排 `config/cataclysm/`。归属不确定时向用户确认。
- 打包完成后检查输出目录，确认上述 YSM 文件夹未被复制。

此规则适用于后续服务端打包，优先于历史制作报告中保留 YSM 自定义模型的旧记录。

## HotAI 补丁文件

- 同一目标类不得同时包含 `.class` 和 `.badiff`。HotAI 1.0 会分别注册两种转换器，可能把已替换的类再次应用差分，生成损坏字节码。
- 新发布或更新补丁时，若有已验证的替换 `.class`，使用该文件分发；目标服务端应先将同目标类的旧 `.class` / `.badiff` 备份到整个 `hotai/` 目录之外，再放入新文件。不要只覆盖 `.class` 而留下旧 `.badiff`。
- HotAI 首次加载通常把 `.class` 转为 `.badiff` 并移除 `.class`。维护中保留其他仍需使用的差分补丁，不要清空整个 `hotai/`。
- 打包与更新完成后，递归检查 `hotai/`，同一相对路径去掉扩展名后必须唯一；所有目标类都应只有一种补丁形式。
