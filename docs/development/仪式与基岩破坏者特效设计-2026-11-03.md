# 仪式与基岩破坏者特效设计

日期：2026-11-03。状态：已实装（2026-11-04），第 8 节的问题已按下表定稿。

## 1. 范围与现状

| 内容 | 实现位置 | 现在的流程 | 现有反馈 |
| --- | --- | --- | --- |
| 结构召唤仪式 | `kubejs/server_scripts/custom_spawn/spawn_struct_base.js`、`spawn_struct.js` | 摆好 3×3×3 结构，手持激活物右键中心方块 B；校验通过后立即拆除结构、消耗激活物、执行召唤 | 成功时一句乱码文字（“TungTungTung”“Samurai X”）；失败时一句“结构召唤失败！” |
| 传送门仪式 | 同上的 `registerPortal`、`spawn_portal.js` | 3×3 地板 A，中心上方 B；右键 B 后立即传送，目的地清出 5×7×5 空间、铺黑曜石返回平台 | 无；维度不对时一句提示 |
| 基岩破坏者 | `kubejs/server_scripts/miscs/bedrock_breaker.js` | 在月球或暮色森林右键基岩，立即传送到下界当前坐标上方 150 格，挖出空间、铺黑曜石 | 一声深板岩铁矿破碎音效 |

已登记的仪式：

- 结构召唤：白金地牢（以太，激活物金色史维特球），武士X（地下花园，激活物乌瑟晶体）。
- 传送门：返回仪式（木棍，回主世界出生点），豆腐世界（豆腐棒），深境一层（深境证书），深境二层（变量卡）。

三者都是“一次右键，瞬间结束”。玩家看不到“仪式在进行”，失败时也不知道哪里摆错了。

## 2. 设计目标

1. **有过程**：成功的仪式有约 2 秒的蓄能和一次明确的释放，玩家知道“我启动了什么”。
2. **失败可诊断**：摆错时直接在世界里标出缺失和错放的方块，而不是只说“失败”。
3. **有主题**：每个仪式按目的地或召唤物配色和配音，豆腐世界和深境看起来不一样。
4. **玩法结果不变**：召唤什么、传送到哪里、消耗什么都不改，只改呈现方式和少量交互细节。需要改玩法的地方列在第 8 节，由你决定。
5. **服务端实现、无需客户端模组**：只用原版粒子、音效、标题和实体，KubeJS 服务端脚本即可完成，客户端不用更新。

## 3. 通用仪式流程（结构召唤与传送门共用）

```text
右键 B ──校验──┬─ 失败 → 诊断（标出问题方块，0.5 秒冷却）
               └─ 成功 → 蓄能（40 tick，每 10 tick 复查结构）
                            ├─ 结构被破坏 / 玩家离开 / 下线 → 中断（不消耗激活物）
                            └─ 完成 → 释放（召唤或传送）→ 余韵（约 3 秒）
潜行 + 右键 B → 预览（只显示整套结构的虚影，不触发）
```

### 3.1 失败诊断

- 缺失或错放的位置上，显示**应放方块的虚影**（原版 `block_marker` 粒子会把方块贴图悬浮在原位，持续约 4 秒）。
- 错放的位置再加一圈红色尘埃粒子，和“缺失”区分开。
- 粒子只发给点击的玩家，不打扰旁人。
- 动作栏给出汇总，替换现在的“结构召唤失败！”。例如：“还差 3 处：冷云 ×2、天使石 ×1”。
- 音效：低音提琴音符（`block.note_block.bass`，音调 0.5）。表示“不对”，不刺耳。
- 不消耗激活物，只加 10 tick 冷却，防止连点刷屏。
- 传送门仪式在错误维度激活时，提示改为“这个仪式只能在主世界进行”，并附同样的低音和一小撮烟。

### 3.2 预览模式

潜行右键 B 时只做展示：所有位置都显示虚影，已放对的位置额外闪一下绿色光点。建造时可以边摆边看，不会误触发。

### 3.3 蓄能（40 tick，约 2 秒）

| 时刻（tick） | 视觉 | 声音 |
| --- | --- | --- |
| 0 | 结构中每个方块各升起一缕主题色粒子，螺旋汇向中心 B；附魔台字符从四周飞向 B | `block.beacon.activate` |
| 0 / 13 / 26 | B 顶部的光柱分三段长高（1 → 2 → 3 格），每段一次小光点爆发 | `block.respawn_anchor.charge`，音调 0.8 → 1.0 → 1.2 |
| 每 10 tick | 静默复查结构（27 个位置，开销可忽略） | — |
| 30–40 | 汇聚粒子加密，B 周围出现一圈缓慢旋转的光环 | `block.amethyst_block.resonate` 渐强 |

中断条件与表现：

- 中断条件：结构被破坏、激活者离中心超过 6 格、激活者下线、死亡或换了维度。
- 中断表现：光柱塌缩成一团烟和火星（`smoke` 加 `electric_spark`），播放 `block.beacon.deactivate`，动作栏“仪式被打断”，不消耗激活物。

同一位置在蓄能期间加锁，防止同时触发两次；结束或中断时解锁。

### 3.4 释放与余韵

**结构召唤**：

1. 冲击波：以 B 为圆心，一圈粒子在 6 tick 内从半径 1 扩到 6。中心一道只有视觉的闪电（不伤人、不点火），配 `entity.evoker.prepare_summon` 和 `item.trident.thunder`。
2. 结构崩解：现在是瞬间清空。改为由外到内分 3 批破坏（角、边、中心，每批间隔 2 tick），每个方块播放原版破坏粒子和音效，不掉落。
3. 召唤结果出现：
   - Boss（武士X）：最后一批崩解 5 tick 后，在中心生成一道烟柱加灵魂火，再生成 Boss。
   - 结构（白金地牢）：在放置区域边缘升起一圈云雾，配 `block.end_portal.spawn`。
4. 标题：16 格内的玩家看到副标题“已召唤：武士X”。保留现在那句乱码文字作为彩蛋，放在聊天栏。
5. 余韵：中心残留 3 秒主题色微光和灰烬。

**传送门**：

1. 出发点：激活者脚下一圈反向传送门粒子向上卷起，周围其他玩家听到 `entity.enderman.teleport`。激活者在传送前听到 `block.portal.travel`（低音量）。
2. 目的地平台：现在是瞬间放下。改为在 10 tick 内“凝结”：先清出空间，再按中心 → 边 → 角的顺序放出黑曜石，每块配放置音效。哭泣的黑曜石最后落位，配 `block.respawn_anchor.set_spawn`。
3. 抵达：脚下一圈主题粒子向上涌起。不再加维度标题，整合包已有 Traveler's Titles，会自动显示维度名称，避免重复。

## 4. 基岩破坏者

### 4.1 交互：连敲三下

现在一次右键就传送，而且是不可逆的单程。建议改成“凿穿”：

| 右键次数 | 表现 |
| --- | --- |
| 第 1 下 | 基岩出现 3 级裂纹（原版挖掘裂纹叠加，所有人可见）；基岩碎屑飞溅；`block.deepslate.hit` 加低音调 `block.anvil.land`；动作栏“基岩出现了裂痕（1/3）” |
| 第 2 下 | 裂纹 6 级；裂缝中冒出熔岩点和余烬，暗示下面就是下界；音效更沉；“（2/3）” |
| 第 3 下 | 裂纹满级后基岩“碎裂”（只播放破坏粒子和音效，方块本身保留）；一道橙红光柱从裂缝冲出；`entity.generic.explode`（低音量）加 `block.respawn_anchor.deplete`；消耗物品，播放 `entity.item.break` |

- 两下之间超过 3 秒，裂纹自动消退，计数归零。
- 计数按玩家加方块位置记录，换一块基岩重新计数。
- 这样能防止误点，过程也和“凿”的手感一致。若希望保持一次右键，可以把三段表现压缩到 1.5 秒自动播放（见第 8 节）。

### 4.2 坠落与抵达

- 传送前 10 tick 给激活者 1 秒黑暗效果，形成“坠入”的转场。
- 抵达下界时，黑曜石平台用与传送门相同的凝结效果生成。四周飘起绯红孢子和灰烬，配 `ambient.nether_wastes.mood`。

### 4.3 在其他维度使用

现在在非月球、非暮色森林的维度右键基岩不会有任何反应。改为：

- 敲出一点火星，配一声金属钝响。
- 动作栏提示“这里的基岩之下没有通路”。
- 不消耗物品。

## 5. 主题配置

在 `registerStructure` / `registerPortal` 的配置里增加可选的 `theme` 字段。未填写时按类型使用默认主题。

| 仪式 | 主色（尘埃渐变） | 点缀粒子 | 特色音效 |
| --- | --- | --- | --- |
| 白金地牢（以太） | 金 → 白 | `end_rod`、`cloud` | `block.amethyst_block.chime` |
| 武士X（地下花园） | 青绿 → 暗绿 | `soul_fire_flame`、`sculk_soul` | `entity.warden.heartbeat`（低音量） |
| 豆腐世界 | 米白 → 浅黄 | `item_snowball`、`cloud` | `block.wool.place`（软） |
| 深境一层 | 砖红 → 橙 | `lava`、`ash` | `block.furnace.fire_crackle` |
| 深境二层（世界树之海） | 青 → 翠绿 | `glow`、`spore_blossom_air` | `block.amethyst_block.resonate` |
| 返回仪式 | 紫 → 黑 | `reverse_portal`、`falling_obsidian_tear` | `block.respawn_anchor.ambient` |
| 基岩破坏者 | 灰 → 橙红 | 基岩碎屑、`lava`、`crimson_spore` | `block.deepslate.hit` |

## 6. 技术方案

- **新增公共模块**：`kubejs/server_scripts/custom_spawn/ritual_fx.js`，提供以下能力，三处功能共用。
  - 主题表。
  - 粒子工具：汇聚、光环、冲击波、光柱、虚影。
  - 时间线执行器：基于 `server.scheduleInTicks`，支持中断。
  - 位置锁。
- **改动现有脚本**：
  - `spawn_struct_base.js`：`spawn` 和失败分支改为调用时间线；`checkStructure` 增加“返回问题位置列表”的版本，供诊断使用。
  - `bedrock_breaker.js`：改为三段计数与时间线；传送和平台逻辑保留。
- **粒子发送**：
  - 公共粒子用服务端 `sendParticles`，只发给 48 格内的玩家。
  - 诊断虚影和预览只发给激活者。
- **其他原版机制**：
  - 裂纹用原版的方块挖掘进度（`destroyBlockProgress`）。
  - 碎裂效果用原版方块破坏事件（`levelEvent 2001`），方块本身不移除。
  - 闪电用只有视觉的闪电实体。
- **可选镜头震动**：灾变模组的屏幕震动实体，用在召唤 Boss 和基岩碎裂两处。整合包已安装该模组，但要先确认能从脚本生成。做成开关，确认不可用时自动跳过。
- **开关**：在 `kubejs/server_scripts/configs.js` 增加 `global.ritualFx`。可分别关闭蓄能（恢复瞬间完成）、黑暗、镜头震动和他人可见的公共粒子。
- **性能预算**：
  - 任何一个 tick 发出的粒子不超过约 200 个。
  - 整段时间线不超过 4 秒。
  - 复查结构每 10 tick 一次，每次 27 个方块。
  - 锁与计数都存在内存中，服务端重启后自然清空。

## 7. 验收要点

1. 两个结构召唤、四个传送门、基岩破坏者在月球和暮色森林各走一遍完整流程，结果与现在一致。
2. 每种仪式各故意摆错一处、缺一处，确认虚影位置、红圈和动作栏汇总都正确；激活物未被消耗。
3. 蓄能中分别拆掉一块结构、走开、下线、死亡，确认都会中断，且不消耗、不召唤、不传送。
4. 同一结构两人同时右键，只触发一次。
5. 多人在场时，旁人能看到公共特效，看不到他人的诊断虚影。
6. 关闭 `global.ritualFx` 各开关后，行为退回现在的瞬间版本。
7. 在服务端用 spark 观察仪式期间的 tick 耗时，无明显尖峰。

## 8. 定稿决定

| 问题 | 决定 |
| --- | --- |
| 蓄能时长 | 统一 40 tick（2 秒），召唤与传送门相同 |
| 激活物消耗时机 | 释放时扣除；蓄能期间换下激活物则中断 |
| 基岩破坏者 | 连敲三下，每下之后用原版物品冷却（8 tick）隔开 |
| 状态效果 | 传送门与基岩破坏者传送前 1 秒黑暗；不用反胃 |
| 镜头震动 | 使用灾变的屏幕震动 |
| 召唤标题 | 只给发起者 |
| 乱码彩蛋 | 保留在聊天栏 |
| 预览与虚影 | 只在空手或手持激活物时出现；手持其他物品右键核心不预览、也不拦截原交互 |

### 双端逻辑

- KubeJS 的 `BlockEvents.rightClicked` 是双端事件，服务端脚本只在服务端收到，客户端脚本只在客户端收到。
- 服务端负责全部判定和效果，所有表现都通过原版命令和数据包下发：
  - 粒子：`particle … force`，公共粒子发给 48 格内的玩家，诊断与预览虚影只发给发起者。
  - 音效：`playsound`。
  - 标题：`title`，只发给发起者。
  - 动作栏：`setStatusMessage`。
  - 裂纹：`destroyBlockProgress`。
  - 屏幕震动：灾变的震动实体，由服务端生成并同步给客户端。
- 客户端脚本在同样的条件下取消本地交互，返回 `FAIL`，客户端就不会预测物品使用，也不会接着对空气使用物品。
- 已在 Forge 47.4 客户端字节码中确认：取消后 `ServerboundUseItemOnPacket` 照常发送，服务端照常收到这次点击。
- 两端用同一份触发表（启动脚本 `global.sdbfRitualTriggers`）。服务端注册仪式时会核对，不在表中的组合在日志中警告。
- 物品冷却由服务端设置并同步到客户端。冷却期间 KubeJS 不会触发右键事件，所以：
  - 蓄能中重复点击自然被挡掉；
  - 快捷栏上的冷却动画就是蓄能进度；
  - 基岩破坏者两下之间的间隔也靠它。
- 挖掘裂纹使用固定的负数 ID：原版不会把裂纹发给与破坏者 ID 相同的实体，用玩家 ID 会导致本人看不到。
- 传送门目的地先放好脚下的哭泣的黑曜石和其下黑曜石，再传送，外圈逐 tick 凝结。玩家抵达时脚下一定有方块。
- 单人游戏同样走内置服务端，行为一致。

### 测试

```text
node docs/tools/test_ritual_fx.cjs
```

用一个简化的 KubeJS 环境加载真实的启动、服务端、客户端脚本，逐 tick 推进，共 52 项检查。覆盖范围：

- 诊断：缺块与错块的虚影只给本人。
- 预览：只在空手或手持激活物且潜行时出现；手持其他物品或不潜行时无反应、不拦截。
- 蓄能：蓄能中重复点击被冷却挡掉；第 40 tick 才扣激活物。
- 召唤释放：分三批崩解、不掉落；标题只给发起者；彩蛋保留。
- 中断：拆块、换物品、走远时都会中断，且不消耗激活物；两人同时激活时第二人提示正在进行。
- 传送门：维度错误时拒绝；传送前 10 tick 黑暗；平台先放支撑、外圈 8 tick 内凝结。
- 基岩破坏者：三下计数与冷却；3 秒不敲则重置；第三下才消耗；坠入下界 150 格上方的黑曜石平台；在其他维度无效。
- 关闭蓄能开关后瞬间完成。
- 客户端与服务端的拦截判断一致。

离线测试无法验证实际画面。进游戏后建议按第 7 节各走一遍，并在多人服务器上确认旁人看到的效果。

## 修复记录

### 2026-11-04：传送门仪式蓄能到一半中止，不传送

- **现象**：单人测试豆腐世界传送仪式时没有传送。KubeJS 日志报错：`spawn_struct_base.js#311: Can't find method net.minecraft.world.entity.Entity.m_20238_(number,number,number)`。
- **原因**：蓄能期间每 10 tick 复查一次玩家距离，用的是 `player.distanceToSqr(x, y, z)`。游戏里 KubeJS 把这个重载名解析成了 `distanceToSqr(Vec3)`，三个数字的调用直接报错。第一次复查时脚本中断，仪式没有释放。原来的锁也没有解开，同一位置会一直提示"仪式进行中"，直到 `/reload`。召唤仪式走同一段代码，也受影响。
- **修复**：
  - 距离改为用 `player.x/y/z` 自己计算。
  - 视觉闪电改用 KubeJS 的 `setPosition`，原来的 `moveTo` 同样是多重载方法。
  - `RitualFx.timeline` 捕获回调里的错误：记录日志、解锁、提示玩家"仪式被打断"，并把激活物冷却改成失败冷却。
- **测试**：`docs/tools/test_ritual_fx.cjs` 的替身模拟了游戏里这两个方法的报错，并在每个场景结束时检查没有脚本错误。新增"蓄能中出错能解锁并再次使用"的场景，共 63 项检查通过。把旧调用放回去，测试会失败。
