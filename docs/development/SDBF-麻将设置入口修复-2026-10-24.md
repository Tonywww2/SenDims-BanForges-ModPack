# 麻将设置入口修复（v3）

适用版本：Minecraft 1.20.1、Riichi Mahjong Forge 0.2.0、HotAI 1.0。用户确认整场已经结束，并且使用麻将扳手仍无法打开牌桌物品栏或设置。

## 原因与证据

本地读取现有模组字节码，并执行原始 `MahjongTableBlock.use` 与 v2 `MahjongTableBlockEntity.onCuteClick`，确认 v2 漏掉两条入口：

1. 方块右键进入 `MahjongTableBlock` 的 `GAME` 分支后，持扳手的玩家不会调用 `onTableRightClick`。即使 driver 已是 `MatchEnded`，事件也直接返回 `CONSUME`。v2 加在 `onTableRightClick` 上的恢复逻辑根本不会执行。
2. 客户端命中模型的可交互节点时，`CuteClickInputHandler` 会取消普通方块右键，发送 `C2SCuteClickPacket`。服务端随后执行 `onCuteClick`，同样绕过 v2 的普通右键恢复入口。

此外，最后一手显示结算后可能仍停在 `RoundEnded + AWAITING_ADVANCE`；只有确认结算、调用 driver 的 `advanceRound`，核心才进入整场结束状态。仅判断 `MatchEnded` 不覆盖这个时刻。

以上遗漏已在本地复现。尚无这次远程点击时的状态记录，不能断言远程只有这一种原因，也未验证远程 v2 文件是否存在重复安装。

## 修改

v3 同时替换 `MahjongTableBlockEntity` 和 `MahjongTableBlock`，保留 v1 三人局循环修复和 v2 整场结束清理。

- 方块中央的扳手请求优先交给新的菜单入口，避免被旧 `GAME` 分支提前消费。
- 模型点击也交给同一扳手菜单入口。服务器使用原有扳手标签识别逻辑。
- 如果整场已结束，调用原有清理流程返回空闲，再通过原有 `NetworkHooks.openScreen` 打开牌桌物品栏。随后可点击原来的设置按钮选择模式。
- 对最后一手已完成结算、尚待确认的情况，使用真实核心的不可变 Match 推演判断确认后是否结束整场。推演使用独立随机数，不推进当前 driver，也不消耗当前对局的随机数；只有确认会结束整场时才实际确认。
- 普通单局结算、仍在进行的对局、未播放完的结算动画不会被扳手提前结束，而会显示“对局或结算尚未结束，暂时无法打开设置。”
- 非扳手模型点击在结算等待确认时也可触发原有确认流程；普通对局中的模型操作继续执行原代码。

这不是对局中途强制终止功能。没有修改网络协议、存档格式、设置菜单或客户端渲染。

## 验证与边界

构建入口：[Build-And-Test.ps1](../tools/server_bugs_2026_10_24/Build-And-Test.ps1)。补丁生成器会核对三个原始类的 SHA-256，并保留 Java 17 类版本。

- 原有 80 项断言通过，覆盖能量反序列化、三人/四人保存与 tick、整场结束清理和再次开局。
- 新增 116 项断言通过，直接执行原始/补丁后的方块右键方法和模型点击方法，而不是只调用新增的辅助方法。
- v2 的两条入口均复现持扳手仍停在 `GAME`、未发送菜单打开请求；v3 的三人/四人终局、待确认的被飞终局及空闲桌均正确请求打开牌桌菜单，随后调用原有模式选择和开局方法成功，人数正确。
- 进行中、普通单局结算及动画中的扳手点击仅提示，不推进对局；方块边缘不误开中央菜单，客户端方块交互不修改服务端状态。
- 三个生成类均通过真实 HotAI `.class → .badiff → 重载` 往返一致性检查，以及 ASM 和 JVM 字节码校验。

麻将 Match/Driver、HotAI 和被测交互方法使用真实代码；Minecraft 世界、物品标签判定、网络发送与 GUI 是测试边界替身。没有启动完整远程服务端或验证客户端实际显示界面，因此仍需现场确认。

## 安装与使用

[下载 v3 麻将补丁](../releases/SDBF-Mahjong-HotAI-2026-10-24-v3.zip)。包内仅有两个麻将替换类、安装说明与校验清单。

1. 完全停止远程服务端。
2. 进入 `hotai/com/riichimahjongforge/mahjongtable/`，把以下两个目标的旧 `.class`、`.badiff` 备份到整个 `hotai` 目录之外，然后移走原位置的旧文件：`MahjongTableBlockEntity`、`MahjongTableBlock`。不要清空其他补丁。
3. 合并 ZIP 内的 `hotai/` 到服务端根目录。两个类必须一起更新，新 Block 会调用新 BlockEntity 的方法。不要把新 `.class` 与旧 `.badiff` 同时留下。
4. 完整启动服务端，`/reload` 不足以加载补丁。首次加载后 `.class` 被转为 `.badiff` 是 HotAI 的正常行为。
5. 结算动画结束后，手持麻将扳手，普通右键牌桌中央；应打开牌桌物品栏，再点设置按钮切换模式。关闭界面，收起扳手，Shift 右键中央重新开局。

联机修复需要服务端安装；联机客户端不必安装新补丁。本地整合包同步了这两个类，重启后供单人/局域网使用。旧本地 v2 差分备份于 `docs/releases/backups/mahjong-v2-2026-10-24/`。

若仍失败，需要该次服务端启动到点击之后的日志，并区分“完全无反应”“出现对局尚未结束提示”“物品栏能打开但设置按钮无反应”。启动日志应包含两个麻将目标类各自的补丁加载记录；牌桌类可能到加载区块时才初始化。
