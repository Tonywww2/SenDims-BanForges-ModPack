# Thermal 树脂提取机性能优化

目标方块：`thermal:device_tree_extractor`。本地版本为 Thermal Foundation 11.0.6.70，内嵌 Thermal Core 11.0.6.24。分析依据为该版本的源码包和实际安装 JAR 中的字节码，已核对一致。

## 原逻辑与开销

`DeviceTreeExtractorBlockEntity.updateValidity()` 先验证已缓存的树叶、原木。缓存失效后，依照朝向搜索三个相邻位置；每个位置先尝试向上生长的树，再尝试向下生长的树。

树干扫描是单条贪心路径，最长到世界高度边界，转向偏移按原实现累计移动。`max_height` 只限制产量计算，不是搜索高度上限；直接用它截断搜索会错过高树树冠，改变配方判定。树叶搜索则是以顶端原木为中心、曼哈顿距离不超过 6 的有限广度优先搜索，最多涉及 377 个位置，并非无限树叶遍历。

确认的性能风险：

1. **每个树干候选方块都创建 Stream、过滤节点及结果数组**。高树以及多条匹配同类原木的配方会放大分配量。
2. 树叶扫描每次从队列取出一个位置都会调用 `Direction.values()`，产生新的方向数组；每个邻接位置还要创建/遍历配方映射的入口集合、迭代器和入口对象。
3. 父类 `DeviceBlockEntity.neighborChanged()` 每次直接调用 `updateValidity()`。红石、管道或其他密集邻居更新可能让同一台机器在同一 tick 内重复检查所有缓存方块，缓存无效时还会重复全扫描。
4. 原方法只对机器周围一格调用 `isAreaLoaded()`，实际树干可能更远，树冠半径为六。后续 `getBlockState()` 没有逐位置的已加载检查，可能同步请求相邻区块。

这些是代码路径上的性能风险，不能据此认定实际服务器已有某个耗时占比，也没有证据表明这里存在不断保留旧世界对象的内存泄漏。

## 补丁行为

- 树干筛选使用两份固定候选数组反复交换，避免按方块创建筛选流水线和新数组；零匹配时保留原候选集合。
- 树叶计数改用平行数组，保留配方对象身份去重、插入顺序、达到上限时的提前返回规则，以及最终相同叶数时优先原先配方的规则。
- 方向数组每次扫描只创建一次。叶列表初始容量最多预分配 376，而不是盲目使用配方中可能很大的 `max_leaves`；实际配方阈值保持原值。
- 已缓存机器在同一 tick 内的重复验证请求合并；被合并的请求会标记待检查，下一 tick 执行，避免漏掉“第一次检查后才长出来”的树。初次放置仍立即检查。
- **产出前强制重新验证**，不受同 tick 合并和未加载重试间隔限制。该次验证调用外，原 `tickServer()` 的产量、增产剂消耗、计时、储罐写入均保持原字节码。
- 树干、树冠、缓存方块和共享树木机器计数只读取已加载区块。遇到未知区块时清除当前提取资格，暂停生产，每 20 tick 重试一次；区块可用后自动恢复。机器紧邻区块卸载时也不会继续利用旧缓存生产。
- 缓存只增加机器自身的五个原始类型字段，没有全局世界/机器缓存，也没有后台扫描线程。

原树形规则、树叶距离六、累计树干转向偏移、向上/向下优先级、最小高度/树叶要求、配方选择顺序、产量公式、升级和增产剂规则均保持。普通邻居变动的状态反映最多延后一个 tick；涉及未加载区块时会暂缓，最长等待下一次一秒重试。

## 验证

执行 `docs/tools/thermal_tree_extractor/Build-And-Verify.ps1`：

- 59 项结构与 HotAI 检查通过，包括原类 SHA-256、未改原方法一致性、ASM 校验、生产强制验证调用和真实 HotAI 首次加载/差分重启一致性。
- 1,891 项差分与行为检查通过。900 组随机世界执行原版和补丁后的实际方法，逐项比较配方、完整原木路径、树叶位置及顺序；补充高达 1,024 格的树、倒生树、重叠及重复配方、树苗生存条件和高度边界。
- 同 tick 连续 100 次邻居验证不会额外读取树木方块；下一 tick 的待检查会执行。生产前砍树会立即使提取失效；未加载树冠不会触发区块读取，恢复加载后可继续工作。
- 强制验证即使抛出配方谓词异常，也会清理强制标志，异常仍向上传递。

离线基准：512 格树干、24 条重叠配方、半径五树冠，预热后测量 240 次扫描，使用 JVM 当前线程分配计数器。

此样本分配量减少约 79%，耗时减少约 42%。数值来自包含世界/方块替身的合成场景，不等同实际 Minecraft 的绝对耗时或服务器 TPS 提升。未启动游戏做实机测试。

## 部署

只新增一个游戏文件：

`hotai/cofh/thermal/core/common/block/entity/device/DeviceTreeExtractorBlockEntity.class`

服务端或单人游戏所在实例需要该补丁，完整重启后生效，不需要改 Thermal JAR 或配方。多人客户端不承担这些服务端扫描逻辑；完整 1102 包另含界面等客户端更新，仍按其说明同步安装。

更新同目标类时，先把原来的 `.class` / `.badiff` 备份到整个 `hotai/` 目录之外，再放入新 `.class`，不要同时保留两种格式。首次启动后 HotAI 将 `.class` 转为 `.badiff` 属于正常行为。1102 更新包安装器会自动备份和处理本包涉及的旧同名补丁。
