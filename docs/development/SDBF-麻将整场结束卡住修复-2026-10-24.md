# 麻将整场结束后无法重新开局的修复

本文为 v2 历史记录。当前版本为 [v3 设置入口修复](SDBF-麻将设置入口修复-2026-10-24.md)，补上扳手方块交互和模型点击入口；请使用 v3 两类更新包。

用户反馈三人局有人被飞后，无法结束或开始下一局，也没有看到结束按钮。附件 `debug-1.log.gz` 覆盖远程服务器 2026-10-24 17:34:02 至 18:00:45，时间按日志原文保留。

## 日志与代码结论

日志第 16769 行确认先前的 `MahjongTableBlockEntity` HotAI 补丁已加载。没有记录此次结算流程的异常栈或 driver 状态快照，不能仅凭日志直接确认现场的内部状态。

对 Riichi Mahjong Forge 0.2.0 原始代码进行复测，确认存在与描述相符的死路：

1. `TheMahjongMatch.advanceRound()` 在规则启用 `bustingEndsGame` 且有玩家点数低于 0 时，将整场状态改为 `ENDED`。
2. `TheMahjongDriver.advanceRound()` 随之进入 `MatchPhase.MatchEnded`。
3. 牌桌的 `advanceRoundAfterResult()` 只清除结算动画、推进 driver 并同步，没有调用 `endGame()`。所以牌桌仍处于 `State.GAME`。
4. `MahjongTableBlock` 在 `GAME` 分支会消费右键；此时结算动画已经清除，点击只进入普通出牌交互，无法结束。重新开局需要 `IDLE`，因此也被挡住。
5. 原始 `onRisingEdge()` 有“driver 已终止时调用 `endGame()`”的分支，所以红石上升沿是原版现有的退出途径。普通右键流程遗漏了这一转换。

原版没有对应的“结束整场”界面按钮。正常单局结算完成后，通过普通右键桌子中央调用 `advanceRoundAfterResult()`；用 Shift 右键中央开启空闲牌桌的新对局。手持模组识别的扳手会进入其他分支。

此前 v1 补丁只改变保存和 tick 中的三个循环上限，没有修改这条结束流程。原始代码即可复现本次状态死路。

## v2 行为

在 v1 的三人局越界修复基础上，只更新同一个 `MahjongTableBlockEntity` 类：

- 在原有结算确认成功推进 driver 后，检查 driver 是否进入 `MatchEnded`。若是，清除结算状态并调用原有 `endGame()`，返回 `IDLE`。
- 对已经卡在 `GAME + MatchEnded` 的牌桌，在普通右键处理入口执行相同检查，使其可以恢复空闲状态。
- 普通单局换局仍保留 driver；还在进行的对局不会因为普通右键结束。
- 等待结算动画的保护条件保留。结算确认前仍展示原有结果；确认后如果整场结束才返回空闲，不自动开始新的整场。
- 继续使用原有 `endGame()` 清理 driver 和随机种子，保留座位布局、占座和牌桌内部物品，不编辑世界 NBT。

## 验证

使用现有模组的真实 Match/Driver 核心，构造已经结束的一手及负点数玩家；直接执行原始/修补后的牌桌方法字节码。Minecraft 世界、玩家与通知边界使用测试替身。

- 原版：确认结算后进入 `GAME + MatchEnded`；普通右键后仍无法返回空闲。
- 新版三人/四人局：确认结算后回到 `IDLE`；原始 `tryStartMatch()` 可再次成功开局，人数正确，座位和牌桌物品保留。
- 普通非终局换局确实推进真实核心，仍保持 `GAME`；普通右键不会结束它。
- 结算动画未完成时，提前确认不会跳过保护条件。
- 已卡住的终局状态可以右键恢复并再次开局；空 driver 的右键安全返回。
- 连同原有能量、三人/四人保存与 tick 检查，共 80 项断言通过。真实 HotAI 的 `.class → .badiff → 再加载` 往返一致，字节码校验通过。

该验证不等同于远程完整模组环境实测。远程服安装后仍需检查已有牌桌恢复，以及实际一场结束后的重新开局。

后续用户反馈右键中央仍无变化，远程 v2 是否成功安装及点击时的牌桌状态尚待确认。进一步读取原版输入代码发现：客户端若命中带 `Interactive` 的模型节点，`CuteClickInputHandler` 会取消普通方块右键并改发 `C2SCuteClickPacket`，服务端进入 `onCuteClick`；v2 的已有终局恢复入口位于 `onTableRightClick`，不覆盖这条模型点击路径。当前没有现场状态或点击记录能确认这就是本次原因，后续应检查两条入口，而非只重复测试牌桌方法。

## 安装与使用

[下载 v2 麻将增量补丁](../releases/SDBF-Mahjong-HotAI-2026-10-24-v2.zip)。目标仍是 `riichi_mahjong_forge-0.2.0.jar`，无需更换 Forge。此包只更新麻将类，保留 FluxOfTetra、任务同步等其他补丁。

1. 停止服务端，备份存档。将旧的 `hotai/com/riichimahjongforge/mahjongtable/MahjongTableBlockEntity.badiff` 或 `.class` 备份到 `hotai/` 目录之外，然后移除原位置的旧文件。
2. 将 ZIP 中的 `hotai/` 合并进服务端根目录，不要清空整个 HotAI 目录。
3. 完整启动服务端；首次加载后 `.class` 转为 `.badiff` 属正常行为。`/reload` 不会更新字节码。
4. 对已卡住的牌桌，空手普通右键桌子中央，使其回到空闲。之后 Shift 右键中央重新开局。
5. 后续单局结算动画结束后，普通右键中央确认；未结束整场时进入下一手，整场已结束时返回空闲，再 Shift 右键中央开启新的一场。

补丁关键行为在服务端生效，联机客户端无需新增模组或更改协议。当前本地整合包也同步此类，重启后生效。
