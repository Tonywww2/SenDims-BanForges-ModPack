# Tetra 采掘适配、普通氧气罐提示与树枝状结晶繁殖

2026-11-02。基于当前整合包的 Tetra 6.9.0、Titan Moon 0.2.0、Thermal Expansion 11.0.1.29 / Core 11.0.6.24。

## 材料范围与问题来源

粗查了模组、KubeJS data 覆盖和实际执行材料生成脚本后的 **223 条材料定义**。其中 140 条归入 S1～S5，其余 83 条为未分期的原版、兼容、插槽或特殊材料定义；这个数量不等于 223 种都能拿来制作同一种工具。

下表格式为范围（中位数）：

| 阶段 | 数量 | 硬度 primary | 密度 secondary | 韧性 tertiary | 材料 toolEfficiency |
| --- | --- | --- | --- | --- | --- |
| S1 | 27 | 0.8～7（1.6） | 0.5～8（1.5） | 0.8～2.9（1.2） | 0～9（6） |
| S2 | 33 | 2～21（3.6） | 1～20（3.3） | 1.3～10（2.3） | 4～12（5） |
| S3 | 32 | 8～26（15） | 0～35（10） | 3.5～13（9.8） | 4.5～8（7） |
| S4 | 36 | 26～84（62） | 12～115（50） | 15～36（33） | 3～10（7） |
| S5 | 12 | 62～95（70） | 18～100（65） | 32～36（34） | 4.5～10（8） |

S1→S5 的中位数：硬度约 **43.8 倍**，密度约 **43.3 倍**，韧性约 **28.3 倍**，材料采掘效率却只有 **1.33 倍**。特别是 S3→S4，密度中位数从 10 到 50，材料效率中位数仍为 7。

原版 `ItemModularHandheld.getDestroySpeed` 会将工具效率乘以 `0.5 × 工具攻速 + 0.5`，最后把结果保底为 1。旧双头工具柄每点密度扣 0.1 攻速，普通单头柄扣 0.2，长柄扣 0.25，绑带另扣 0.1；锤头还有密度扣速。这些系数原本服务于个位数材料密度。如今密度 65 的双头柄单是材料部分就扣 6.5，足以把工具的基础攻速 4 扣穿，采掘结果便退化为徒手速度。

## 新的采掘节奏模型

不改材料本身的数值；在 15 个采掘相关模块中重新标定 **攻速提取**。硬度代表工具头的切削推进，密度仍代表重量负担，韧性为柄和绑带提供稳定性补偿。

各系数都是“每点材料属性带来的工具攻速增减”，不是百分比：

| 模块 | 硬度加成 | 密度扣除 | 韧性补偿 |
| --- | --- | --- | --- |
| 镐头 | +0.006 | 无 | 无 |
| 斧头 | +0.005 | 无 | 无 |
| 锤头 | +0.004 | −0.003（原来带密度扣速的变体） | 无 |
| 锛头 | +0.004 | 无 | 无 |
| 撬爪 | +0.004 | 无 | 无 |
| 锄头 | +0.006 | 无 | 无 |
| 镰刀头 | +0.007 | 无 | 无 |
| 铲头 | +0.008 | 无 | 无 |
| 解放地穿刺头 | +0.004 | −0.004 | 无 |
| 双头工具柄 | 无 | −0.004 | +0.010 |
| 普通单头柄 | 无 | −0.005 | +0.010 |
| 轻型单头柄 | 无 | −0.0025 | +0.012 |
| 长柄 | 无 | −0.006 | +0.008 |
| 单头 / 双头绑带 | 无 | −0.002 | +0.004 |

保留原有固定攻速差、耐久、完整度、魔容量、采掘等级、工具效率提取、材料类别、双镐/双锤等级协同，以及撬动、整地、横扫、穿刺等功能。轻柄仍更灵活，长柄与锤仍更重；同一攻速属性也会影响这些工具的近战节奏。普通单头柄与轻/长柄也供矛、三叉戟等单头组合使用，因此它们的密度扣速一并得到修正；没有改写这些武器头。

## 树枝状结晶繁殖

配方 ID：`sdbf:branch_crystal_hydrogen_propagation_s5`。

```text
有机灌注机 thermal:insolator
树枝状结晶 ×1 + 1000 mB #forge:hydrogen + 16000 RF
→ 树枝状结晶 ×2（基础产出，仍参与原机肥料机制）
```

结晶为 `titan_moon:branch_crystal`。液体使用原模组已有的 `forge:hydrogen` 流体标签，通过 CoFH 的 `fluid_tag` 字段声明；该标签包含 Titan 的液态氢及流动态，也兼容同标签下其他流体。配方显式声明流体，序列化器便不会额外添加默认水。

需要配套的 **单类 HotAI 补丁**：原版灌注机储罐验证器只接受水，而且其单物品配方管理器不会核对流体类型。补丁将储罐改为接受水或氢，并在配方缓存结果返回前核对流体：氢配方只接受氢标签，普通水配方继续只接受水。原管理器将流体标签展开成具体流体、但只按物品索引，补丁因此重新查询整个氢标签，兼容标签中的不同成员和标签刷新。

补丁保留原机的数量校验、实际消耗、能耗、肥料、循环处理、输出和其他方法；不修改 Thermal JAR。目标类为 `cofh.thermal.expansion.common.block.entity.machine.MachineInsolatorBlockEntity`。
