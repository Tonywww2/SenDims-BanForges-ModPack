# 万象合金实装记录

对应第四版设计，保留 141 个工艺位置：7 个原生供料位置，以及 134 个加工与最终合成位置。179 条普通配方和 13 条带原生载体检查的封装配方均直接写在服务端脚本中，共 192 条本路线配方。材料注册目录、封装说明和加载检查清单内嵌于启动脚本，无需外部配置文件。

累计取消的 28 个流程不在当前路线中，包括核工分析仪与豆腐承重硬化。盐卤凝固产物直接进入陶瓷承压膜装配，靶室产物直接进入中子约束环总装。阶段五入口和八个最终部件均逐批消耗。

## 接口衔接

- 亚原子液化机只接收流体。在衰变加速的固体产物与液化机之间增加核工熔化步骤，整份材料依次消耗。
- 热力药水酿造机的原生管理器支持一份物品与一份流体输入、专用流体输出。相变抑制酿液在该机器中制备，再灌装为本段构件。
- 铣床先通过 `step1` 将一份整合材料铺为 25 片导电箔，再通过 `step1: false` 的完整 5×5 图案与催化材料消耗全部导电箔，得到一个装配件。
- 固体裂变与熔盐反应堆使用原生燃料及乏燃料，再消耗对应乏燃料封装。灵魂绑定沿用整合包既有带电灵魂过滤片。
- 凝矿兰、石莲和世界内转化使用各不相同的前驱方块。每个新增前驱只有一条目标转化，掉落表每次只给一份。
- 所有新增核工流体配方使用明确的单流体标签；满桶参与装配时沿用容器返还规则。

## 验证结果

已通过静态资源检查：物品／流体引用、配方类型、合成槽位、真实配方消耗边、中文名称、方块掉落、取消项清理，以及缺少阶段五入口时不能得到八个部件或最终锭。

脚本测试已检查注册目录一致性、封装配方的两次重载，以及状态拒绝／接受分支：曝光不足的 PCB、错误或喝过的药水、空胶卷、无有效标识的照片、张数不足或含无效照片的照片叠都不能得到构件。

这些检查未启动 Forge，也未实际操作机器。新增注册需要完整重启游戏。进入世界后先检查 `logs/kubejs/server.log` 中的 `[万象合金] 加载检查通过`；它只确认注册与配方加载，世界内转化、机器产量和整条路线试制仍按设计文档中的验收项逐项验证。

脚本迁移逐一核对全部 179 条普通配方的对象和 ID，与迁移前完全一致。原来的数据包配方副本已移除，避免重复注册。现有气动炼油节点的输出数量问题仍在 HTML 预览中标注，迁移未改变该配方参数。
